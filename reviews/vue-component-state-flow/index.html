관제판에 표시할 가상 수량을 부모 화면과 자식 패널에 함께 보여 줍니다. 자식 버튼을 눌렀는데 부모 숫자까지 바뀌려면 어떤 연결이 필요할까요? 부모가 값을 내려주고, 자식이 변경을 요청하고, 부모가 실제 값을 바꾸는 과정을 직접 확인합니다.

컴포넌트는 화면을 구성하는 부품입니다. 부모·자식은 사람이나 서버가 아니라 부품의 포함 관계입니다. 이 글에서는 App.vue가 부모이고, 그 안에서 사용하는 CounterPanel.vue가 자식입니다. 두 컴포넌트는 같은 브라우저 안에서 동작합니다. 이전 복습의 파일은 필요하지 않습니다. 표시 시간 35분은 편성용 추정이며 학습자 실측이 아닙니다.

이번 편은 숫자 상태 하나와 부모·자식 한 쌍에 집중합니다. 입력 연결은 별도 복습에서 다루며, 생명주기·slot·provide/inject·Router·Pinia·HTTP 요청과 교안 p158의 네 부품 분리 과제 전체는 후속으로 남깁니다. 스타일 꾸미기·데이터 저장·외부 배포는 하지 않습니다.

01새 폴더에서 두 컴포넌트 열기

개인 Mac의 터미널·편집기·브라우저와 이미 준비된 Node.js·npm을 사용합니다. Node.js는 개발 도구를 실행하며 npm은 필요한 패키지를 설치합니다. 학습 환경은 Node 22 계열의 22.18 이상, 24 계열의 24.12 이상 또는 26 계열을 권장합니다. 실행 검증 환경은 Node 26.7.0, npm 11.19.0입니다. 다른 OS와 버전은 미확인입니다.

현재 위치·기존 파일·버전을 확인합니다. 명령을 찾을 수 없거나 환경이 맞지 않으면 멈추고 준비 도움을 요청하세요. 이 글에서는 전역 설치나 버전 교체를 하지 않습니다.

pwd

현재 폴더의 절대 경로가 나옵니다. 다음으로 기존 파일을 확인합니다.

ls

파일 목록이 보이거나 빈 폴더면 출력이 없습니다. 이 파일들은 수정하지 않습니다.

node --version

Node 버전이 v로 시작해 표시됩니다.

npm --version

npm 버전 숫자가 표시되면 사용할 수 있습니다. 이어서 이번 서버에 쓸 5177번 포트를 확인합니다. 포트는 같은 컴퓨터 안에서 서버를 구분하는 번호입니다.

lsof -nP -iTCP:5177 -sTCP:LISTEN

출력이 없으면 이 조회에서 대기 서버를 찾지 못한 것입니다. 이때 종료 코드 1은 가능하며 오류 문구가 없는지 함께 확인합니다. 목록이 나오면 다른 프로세스를 종료하지 말고 멈추세요. 실제 빈 포트 여부는 서버 시작 때 한 번 더 확인합니다.

기존 파일과 섞이지 않는 새 임시 폴더를 만듭니다.

NBP_REVIEW_ROOT="$(mktemp -d /tmp/nbp-vue-component.XXXXXX)"

정상일 때 화면 출력은 없고 새 폴더 경로가 변수에 저장됩니다. 오류가 나오면 다음 명령으로 진행하지 않습니다.

cd "$NBP_REVIEW_ROOT"

정상 이동은 출력이 없습니다. 실제 위치를 확인합니다.

pwd

/tmp/nbp-vue-component.로 시작하는 새 경로여야 합니다. Mac에서는 실제 위치가 /private/tmp/ 아래로 표시될 수도 있습니다. 이 경로를 편집기의 폴더 열기에 사용하세요.

ls -A

아직 비어 있어 출력이 없어야 합니다. 기존 파일이 보이면 멈추고 새 폴더인지 확인합니다.

mkdir src

출력 없이 src 폴더가 만들어집니다. 편집기에서 아래 여섯 파일을 각각 새로 만들고 파일 이름과 확장자를 그대로 저장하세요. src는 소스 코드를 모을 하위 폴더입니다. 준비 도구를 직접 구성하므로 교안의 create-vue 생성 명령은 추가로 실행하지 않습니다.

실행에 필요한 네 파일

package.json은 설치할 패키지와 실행 명령 목록입니다. Vue는 화면 갱신을 담당하고 Vite는 .vue 파일을 브라우저가 실행할 수 있도록 처리하는 개발 도구입니다. Vue 플러그인은 Vite에 .vue 처리 기능을 연결합니다. 버전 앞에 ^ 등을 붙이지 않고 아래 그대로 작성합니다.

package.json 전체:

{
  "name": "nbp-vue-component-review",
  "private": true,
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5177 --strictPort"
  },
  "dependencies": {
    "vue": "3.5.42"
  },
  "devDependencies": {
    "vite": "8.3.0",
    "@vitejs/plugin-vue": "6.0.9"
  }
}

127.0.0.1은 자기 컴퓨터만 가리킵니다. --strictPort는 5177번을 쓸 수 없을 때 다른 번호로 옮기지 않고 중단하게 합니다.

vite.config.js 전체:

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
})

index.html 전체입니다. #app 자리에 Vue 화면을 넣고, main.js에서 시작합니다.

<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Vue 부모와 자식 복습</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>

src/main.js 전체입니다. import는 다른 파일이나 패키지에서 기능을 가져옵니다. ./App.vue는 이 파일과 같은 폴더에 있는 부모 화면입니다.

import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')

부모와 자식 파일

.vue 파일 하나에 상태·함수를 쓰는 <script setup>과 화면 모양을 쓰는 <template>을 함께 둡니다. 이런 형식을 단일 파일 컴포넌트(SFC)라고 합니다. <p>는 문단, <button>은 버튼이며 <CounterPanel />은 우리가 가져온 자식 부품입니다.

ref(0)은 Vue가 변경을 화면에 반영할 수 있는 값 보관소를 만들고 처음 값으로 숫자 0을 넣습니다. const count는 그 보관소의 이름입니다. script에서는 count.value로 안의 값을 읽고 바꾸지만 template에서는 {{ count }}로 표시합니다. 중괄호 두 쌍은 글자를 그대로 찍는 대신 현재 값을 표시하는 자리입니다.

function increaseBy(amount)는 나중에 실행할 동작의 이름과 받을 값의 이름을 정합니다. amount는 호출할 때 전달받는 변경량입니다. count.value = count.value + amount는 현재 값에 변경량을 더한 결과를 다시 저장합니다. 두 파일을 먼저 전부 저장하고, 다음 단계에서 연결을 하나씩 관찰합니다.

src/App.vue 전체:

<script setup>
import { ref } from 'vue'
import CounterPanel from './CounterPanel.vue'

const count = ref(0)

function increaseBy(amount) {
  count.value = count.value + amount
}
</script>

<template>
  <main>
    <h1>관제판 수량</h1>
    <p>부모 수량: {{ count }}</p>
    <button @click="increaseBy(1)">부모에서 1개 추가</button>
    <CounterPanel :count="count" @add="increaseBy" />
  </main>
</template>

src/CounterPanel.vue 전체:

<script setup>
defineProps({ count: Number })
const emit = defineEmits(['add'])

function requestAdd() {
  emit('add', 1)
}
</script>

<template>
  <section>
    <h2>자식 패널</h2>
    <p>자식이 받은 수량: {{ count }}</p>
    <button @click="requestAdd">부모에게 추가 요청</button>
  </section>
</template>

defineProps는 자식이 받을 값, defineEmits는 자식이 보낼 이벤트 이름을 선언합니다. 둘은 <script setup>을 처리할 때 Vue가 알아보는 작성 규칙이므로 별도의 import가 없습니다. Number는 숫자를 받겠다는 뜻이고 ['add']는 사용할 이벤트 이름을 담은 목록입니다. 구체적인 전달 순서는 2·3단계에서 확인합니다.

여섯 파일을 저장한 뒤 새 학습 폴더의 터미널에서 설치합니다. 현재 사이트나 다른 프로젝트에서 실행하지 마세요.

npm install

정상 종료하면 node_modules 폴더와 package-lock.json이 생깁니다. 설치 개수·소요시간은 환경마다 다릅니다. 네트워크·권한 오류 또는 보안 취약점 보고가 나오면 성공으로 넘기지 말고 출력을 보존해 도움을 요청하세요. sudo, 전역 설치, npm audit fix --force로 해결하지 않습니다.

개발 서버를 시작합니다. 이 터미널은 종료 단계까지 그대로 둡니다.

npm run dev

터미널에 http://127.0.0.1:5177/이 표시되어야 합니다. 포트 충돌이나 파일 오류가 나오면 멈추고 메시지의 경로와 저장 내용을 확인하세요. 브라우저에서는 HTML 파일을 더블클릭하지 않고 이 주소를 엽니다. 정상 첫 화면은 부모·자식 수량이 모두 0이며 버튼이 두 개 있습니다.

조작: 새 학습 폴더의 여섯 파일을 저장하고 npm run dev로 표시된 주소를 브라우저에서 엽니다. 아직 버튼은 누르지 않습니다.

02부모의 값을 자식에게 내려주기

부모에서만 숫자를 바꾸면 자식의 표시는 그대로일까요? 클릭하기 전에 예상해 보세요. App.vue에는 다음 연결이 있습니다.

<CounterPanel :count="count" @add="increaseBy" />

:count="count"에서 왼쪽 count는 자식의 입력 이름이고 오른쪽 count는 부모가 가진 값입니다. 콜론 :은 v-bind의 줄임말로, 오른쪽을 고정 글자가 아닌 JavaScript 값으로 전달합니다. count="count"처럼 콜론을 빼면 숫자 상태가 아니라 글자 count가 전달되므로 그대로 유지하세요.

자식의 defineProps({ count: Number })가 이 입력을 받습니다. 부모가 내려주는 입력을 prop이라고 부르며, 자식은 이 숫자를 읽어 표시합니다. 이 예제에서 원본 숫자의 소유자는 부모입니다. 자식이 받은 숫자 prop에 직접 대입해 부모 상태를 바꾸는 방식은 사용하지 않습니다. Vue의 단방향 props 설명도 이 경계를 따릅니다.

부모 버튼의 @click="increaseBy(1)"은 클릭하면 부모 함수를 변경량 1로 실행하라는 뜻입니다. 부모 숫자가 바뀌면 연결된 자식 표시도 같은 값으로 갱신됩니다.

브라우저 실행

대상: http://127.0.0.1:5177/

조작: App.vue와 CounterPanel.vue가 준비 단계 코드로 저장돼 있는지 확인하고 새로고침합니다. 부모에서 1개 추가 버튼만 한 번 누릅니다.

확인: 처음에는 두 수량이 0으로 보이고, 클릭 뒤 부모 수량과 자식이 받은 수량이 모두 1로 보입니다.

숫자가 다르면 :count="count"와 자식의 count 철자, 저장한 파일 위치를 확인하세요. 부모·자식 파일이 있다고 해서 자동으로 값을 공유하는 것은 아닙니다. 어떤 코드가 두 표시를 이어 주었는지 자기 말로 짚어 보세요.

작은 변형: src/App.vue의 const count = ref(0)에서 초기값만 3으로 바꾸고 저장·새로고침하세요. 두 화면의 시작값을 예상한 뒤 부모 버튼을 한 번 누릅니다. 자식 파일을 바꾸지 않았는데 자식 표시도 달라진 이유를 설명해 보세요. 다음 단계 전에 초기값을 0으로 복원하고 저장·새로고침합니다.

완료 예시

원형 두 파일을 저장하고 새로고침한 뒤 부모 버튼을 한 번 눌러 확인한 비교표입니다.

옆으로 밀어서 비교 →
상태부모 수량자식이 받은 수량
새로고침 직후00
부모 버튼 한 번11

부모의 increaseBy(1)이 count.value를 1로 바꿉니다. :count="count"로 연결한 자식 입력도 1을 받아 표시합니다. 자식 버튼은 아직 누르지 않았습니다.

변형은 부모의 선언 한 줄만 const count = ref(3)으로 바꿉니다. 새로고침 직후 두 수량 3, 부모 버튼 한 번 뒤 두 수량 4를 확인했습니다. 자식의 입력은 부모의 현재 값을 받으므로 같은 값이 표시됩니다. 확인 뒤 const count = ref(0)으로 복원합니다.

03자식의 요청을 부모가 처리하기

이번에는 자식 버튼만 누릅니다. 자식 파일에는 부모의 count.value를 수정하는 줄이 없는데 어떻게 값이 바뀔까요?

@는 이벤트가 발생했을 때 실행할 동작을 연결합니다. 자식 버튼의 @click="requestAdd"는 브라우저 클릭을 자식 함수에 연결하고, 부모의 @add="increaseBy"는 자식이 보내는 add 이벤트를 부모 함수에 연결합니다. 이름이 같은 함수가 자동으로 실행되는 것이 아니라 이 연결이 필요합니다.

emit('add', 1)의 첫 값 'add'는 이벤트 이름, 두 번째 값 1은 함께 전달할 데이터입니다. 함께 보내는 데이터를 payload라고 부릅니다. 여기서는 “1만큼 늘려 달라”는 변경량입니다. emit은 부모 상태를 직접 바꾸지 않습니다. 전달받은 1이 부모 함수의 amount로 들어가고, 그 함수가 실제 대입을 수행합니다. Vue 컴포넌트 이벤트에서 이벤트 인자와 처리 함수의 연결을 확인할 수 있습니다.

자식 버튼 클릭 → requestAdd → emit('add', 1)
  → 부모의 @add 연결 → increaseBy(1) → count.value 변경
  → 부모 표시 갱신 + :count로 내려간 자식 표시 갱신

브라우저 실행

대상: http://127.0.0.1:5177/

조작: 원형 App.vue와 CounterPanel.vue를 저장한 상태에서 새로고침하고 부모에게 추가 요청 버튼을 한 번, 이어서 한 번 더 누릅니다. 부모 버튼은 누르지 않습니다.

확인: 처음에는 두 수량이 0으로 보입니다. 한 번 클릭하면 함께 1로, 다음 클릭 뒤 함께 2로 바뀝니다.

클릭해도 0이면 자식의 'add'와 부모의 @add, 처리 함수 이름을 대조하세요. 경고나 오류가 나오면 임의로 prop을 수정하지 말고 해당 파일을 원형으로 복원해 저장한 뒤 새로고침합니다. emit과 부모의 상태 대입 중 어느 쪽이 값을 실제로 바꾸는지 설명해 보세요.

작은 변형: src/App.vue의 자식 태그에서 @add="increaseBy" 부분만 잠시 지웁니다. 자식의 emit과 부모 함수는 그대로 둔 채 저장·새로고침하고 자식 버튼을 두 번 누르세요. 이번에는 두 숫자가 바뀔지 먼저 예상합니다. 결과를 확인한 뒤 왜 함수가 있어도 실행되지 않는지 설명하세요. 다음 단계 전에 지운 연결을 다시 넣고 저장·새로고침하여 자식 버튼이 작동하는지 확인합니다.

완료 예시

자식은 emit('add', 1)을 실행하고, 부모는 @add="increaseBy"로 받은 요청을 처리했습니다. 두 표시가 함께 바뀌는 것을 확인했습니다.

옆으로 밀어서 비교 →
상태부모 수량자식이 받은 수량
새로고침 직후00
자식 버튼 한 번11
자식 버튼 두 번22

실제 변경 줄은 부모의 count.value = count.value + amount입니다. defineProps는 입력 선언이고 emit은 요청 전달이므로 둘만으로 부모 값을 자동 갱신하지 않습니다.

변형한 자식 태그는 <CounterPanel :count="count" />입니다. 새로고침 뒤 자식 버튼을 두 번 눌러도 두 수량은 0으로 남았습니다. 요청을 부모 함수에 연결하지 않았기 때문입니다. <CounterPanel :count="count" @add="increaseBy" />로 복원하고 저장·새로고침하면 자식 클릭마다 다시 0→1→2로 바뀝니다.

04보내는 변경량 하나만 바꾸기

자식이 한 번 요청할 때 2씩 늘리려 합니다. 자식 함수의 전달 데이터 한 곳만 바꾸세요. 수정할 파일은 src/CounterPanel.vue, 위치는 requestAdd 안의 emit('add', 1)입니다. 이벤트 이름과 부모 코드는 그대로 둡니다. 아직 아래 완료 예시를 펼치지 말고 어느 숫자를 바꿀지 정하세요.

저장만 하면 개발 도구가 화면을 갱신할 수 있지만, 앞서 누른 횟수의 영향을 없애려면 이번에는 반드시 브라우저를 새로고침합니다. 초기값 0에서 한 번·두 번 클릭하면 무엇이 보일지 먼저 예상하세요.

브라우저 실행

대상: http://127.0.0.1:5177/

조작: CounterPanel.vue의 requestAdd에서 전달하는 변경량만 2로 바꾸고 저장합니다. 새로고침해 두 수량 0을 확인한 뒤 부모에게 추가 요청 버튼을 한 번, 이어서 한 번 더 누릅니다.

확인: 한 번 누르면 두 수량이 2로, 두 번 누르면 두 수량이 4로 보입니다. 부모 버튼과 부모 함수는 수정하지 않았습니다.

예상과 다르면 변경한 파일·저장·새로고침과 emit의 두 번째 값을 확인하세요. 부모 함수를 바꾸지 않았는데 증가량이 달라진 이유를 “자식이 보낸 값 → 부모가 받은 값 → 상태 대입” 순서로 말해 보세요. 다음 종료 단계는 변형 그대로 진행합니다. 원형을 다시 연습하려면 같은 자리의 2를 1로 돌리고 저장·새로고침하면 됩니다.

완료 예시

실행해 확인한 변형 src/CounterPanel.vue 전체입니다. src/App.vue는 준비 단계 코드 그대로 둡니다.

<script setup>
defineProps({ count: Number })
const emit = defineEmits(['add'])

function requestAdd() {
  emit('add', 2)
}
</script>

<template>
  <section>
    <h2>자식 패널</h2>
    <p>자식이 받은 수량: {{ count }}</p>
    <button @click="requestAdd">부모에게 추가 요청</button>
  </section>
</template>

새로고침 직후 두 수량은 0, 한 번 클릭 뒤 2, 두 번 클릭 뒤 4를 확인했습니다. 바뀐 것은 payload뿐입니다. 부모의 amount가 2를 받아 매번 2를 더하며, 결과는 prop으로 자식에게 다시 전달됩니다.
