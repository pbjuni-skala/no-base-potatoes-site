도시를 바꾸면 제목도 바뀌고, 아래에는 어디에서 어디로 바뀌었는지 기록이 쌓입니다. 둘 다 화면이 달라지지만 역할은 다릅니다. 제목은 현재 선택으로 계산할 수 있고, 변경 기록은 이전 선택과 새 선택을 함께 알아야 남길 수 있습니다.

이번 목표는 computed와 watch를 바꿔 쓸 기능으로 보지 않고, 현재 값의 계산과 변경 후 동작을 구별하는 것입니다. 클릭으로 ref 상태를 바꾸고 보간으로 화면에 표시하는 기본을 사용합니다. 이전 글의 파일은 필요 없습니다. 학습용 자격 증명도 필요 없으며 실제 자격 증명·개인정보는 사용하지 않습니다. 30분은 실측하지 않은 편성용 추정입니다.

01새 프로젝트에서 준비 화면 열기

macOS 터미널, 편집기와 Chrome·Edge 같은 브라우저를 사용합니다. Node.js와 npm은 이미 설치되어 있어야 합니다. Node 22.18 이상인 22 계열, 24.12 이상인 24 계열 또는 26 계열을 사용하세요. Node는 개발 도구를 실행하고 npm은 필요한 패키지를 설치합니다. 설치되지 않았다면 여기서 도움을 받으세요.

파일 탐색기에서 기존 프로젝트 밖에 새 빈 폴더 nbp-vue-watch-review를 만들고 편집기로 엽니다. 이름이 이미 있으면 덮어쓰지 말고 다른 새 폴더를 선택합니다. 아래 경로는 모두 그 폴더 기준이며, 이전 복습 파일은 필요 없습니다. 폴더의 터미널에서 각각 실행합니다.

pwd
node --version
npm --version

정상이라면 새 폴더의 절대 경로와 버전 번호가 나옵니다. 다른 프로젝트 경로나 지원하지 않는 버전이면 중단합니다. 이번에 사용할 포트도 확인합니다.

lsof -nP -iTCP:5182 -sTCP:LISTEN

프로세스 행이 없어야 합니다. 행이 나오면 다른 서버를 끄지 말고 멈추세요. 아래 다섯 파일을 편집기로 새로 만듭니다. src 폴더도 만들고 모두 UTF-8로 저장합니다.

package.json 전체입니다. 고정 버전으로 설치하며 --strictPort는 포트 충돌 때 다른 주소로 옮기지 않고 멈추게 합니다. 127.0.0.1은 자신의 컴퓨터에서 접속하는 주소입니다.

{
  "name": "nbp-vue-watch-review",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5182 --strictPort"
  },
  "dependencies": {
    "vue": "3.5.42"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "6.0.9",
    "vite": "8.3.0"
  }
}

vite.config.js 전체입니다. Vite는 개발 서버이며 Vue 플러그인이 .vue 파일을 처리합니다.

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({ plugins: [vue()] })

index.html 전체입니다. #app에 Vue 화면을 연결합니다.

<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>

src/main.js 전체입니다. import는 다른 파일이나 패키지에서 기능을 가져옵니다.

import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')

src/App.vue 전체입니다. Vue의 SFC는 JavaScript와 화면 틀을 한 .vue 파일에 모으는 형식입니다. 지금은 화면 틀인 template만 사용합니다.

<template>
  <main>
    <h1>도시 변경 기록</h1>
    <p>실습 준비</p>
  </main>
</template>

새 폴더의 터미널에서 패키지를 설치합니다. 네트워크가 필요하며 이 폴더에 node_modules와 package-lock.json이 생깁니다. 전역 설치가 아닙니다.

npm install

정상이라면 오류 없이 끝납니다. 권한·네트워크·버전 오류가 있으면 멈추고 원인을 확인합니다. sudo나 전역 설정 변경으로 우회하지 않습니다. 이어서 서버를 시작합니다.

npm run dev

터미널에 http://127.0.0.1:5182/가 표시되어야 합니다. 서버 터미널은 열어 둡니다. 파일을 더블클릭하지 말고 다음 주소를 여세요.

02현재 제목과 변경 이력을 함께 보기

computed는 선택된 도시에서 제목을 계산합니다. 반면 watch는 첫 인자로 감시할 ref 자체를 받고, 그 값이 바뀌면 두 번째 인자의 함수를 실행합니다. 이 함수의 인자 순서는 새 값, 이전 값입니다. 출력 문장은 읽기 편하도록 이전 값부터 이어 붙입니다.

예상해 보세요. 초기값이 서울이라고 해서 아직 하지 않은 도시 변경이 기록될까요? 아래 src/App.vue 전체를 저장하고 새로고침합니다.

<script setup>
import { ref, computed, watch } from 'vue'

const selectedCity = ref('서울')
const heading = computed(() => selectedCity.value + ' 관측 화면')
const changes = ref([])
watch(selectedCity, (newCity, oldCity) => {
  changes.value.push(oldCity + ' → ' + newCity)
})
</script>

<template>
  <main>
    <h1>{{ heading }}</h1>
    <button type="button" @click="selectedCity = '서울'">서울 선택</button>
    <button type="button" @click="selectedCity = '수원'">수원 선택</button>
    <button type="button" @click="selectedCity = '부산'">부산 선택</button>
    <p>변경 기록: {{ changes.length }}개</p>
    <ol>
      <li v-for="(change, index) in changes" :key="index">{{ change }}</li>
    </ol>
  </main>
</template>

changes는 기록 문자열의 배열입니다. push는 끝에 항목을 추가합니다. 이 예제는 끝에 추가만 하므로 기록 순번을 key로 썼습니다. 항목을 정렬·삭제하는 일반 목록에는 안정적인 고유 id가 필요합니다.

브라우저 실행

대상: http://127.0.0.1:5182/

조작: src/App.vue를 위 코드로 저장하고 새로고침합니다. 초기 상태를 읽고 수원 선택을 한 번 클릭한 뒤 화면 갱신을 기다립니다.

확인: 처음은 서울 관측 화면과 변경 기록: 0개입니다. 수원 선택 후 수원 관측 화면, 변경 기록: 1개와 서울 → 수원이 보입니다.

기본 watch는 등록할 때 즉시 실행하지 않습니다. 이 글은 즉시 실행 옵션을 사용하지 않으므로 처음 기록이 없는 것이 정상입니다. 클릭 처리 직후의 코드와 화면 갱신은 같은 순간이라고 가정하지 말고 화면이 반영된 뒤 읽습니다.

작은 변형: 화면이 수원일 때 수원 선택을 한 번 더 누른 뒤, 부산 선택을 누르세요. 클릭 횟수와 기록 개수가 같을까요? 이유를 말한 뒤 새로고침해서 서울·0개로 돌려놓습니다.

watch는 버튼 클릭 횟수가 아니라 감시 중인 문자열 값의 변화를 봅니다. 수원에 수원을 다시 대입하면 값이 달라지지 않아 기록이 추가되지 않습니다. 제목은 현재 값만으로 계산하고 기록은 watch가 배열에 남깁니다.

03감시하는 상태 하나를 바꾸어 비교하기

watch가 화면 전체의 모든 변화를 자동으로 기록하는 것은 아닙니다. 위 코드의 감시 대상은 selectedCity 하나입니다. 이번에는 제목이 계속 바뀌어도 기록이 안 남도록, 감시 대상만 다른 ref로 연결해 봅니다. 의도적으로 연결을 달리하는 실험이지 정상 코드의 개선은 아닙니다.

먼저 예상하세요. 새 ref의 초기 글자가 서울로 같으면 두 ref가 같은 상태일까요? src/App.vue의 script setup 부분만 아래로 바꾸고 나머지 template은 유지합니다. 이것은 부분 수정 코드입니다.

import { ref, computed, watch } from 'vue'

const selectedCity = ref('서울')
const untouchedCity = ref('서울')
const heading = computed(() => selectedCity.value + ' 관측 화면')
const changes = ref([])
watch(untouchedCity, (newCity, oldCity) => {
  changes.value.push(oldCity + ' → ' + newCity)
})

브라우저 실행

대상: http://127.0.0.1:5182/

조작: src/App.vue의 script setup 안을 위 코드로 교체해 저장하고 새로고침합니다. 수원 선택을 클릭합니다.

확인: 제목은 수원 관측 화면으로 바뀌지만 변경 기록은 0개로 보입니다.

untouchedCity라는 ref는 만들어졌지만 버튼은 여전히 selectedCity만 바꿉니다. 따라서 제목과 기록이 서로 다른 상태에 연결됩니다. 화면이 바뀌었다는 사실만으로 watch가 실행됐다고 판단할 수 없습니다.

작은 변형: 감시 대상 한 단어를 untouchedCity에서 selectedCity로 복원하고 새로고침한 뒤 수원을 누릅니다. 기록이 돌아오는 이유를 설명하세요. 마지막에는 앞 단계의 전체 App.vue로 복원하고 저장합니다.

04서버를 종료하고 학습 파일 남기기

지금까지 만든 파일을 저장합니다. 새로고침은 실행 중 메모리 상태를 초기화하지만 파일을 지우지는 않습니다. 이 단계에서는 삭제 명령을 실행하지 않습니다. 정상이라면 터미널 프롬프트와 브라우저의 연결 실패 안내가 보입니다.

브라우저 실습 종료

대상: http://127.0.0.1:5182/

종료 방식: 서버 터미널 Ctrl+C

조작: 자신이 npm run dev로 시작한 해당 서버 터미널에서 Ctrl+C를 누르고 대상 URL을 브라우저에서 새로고침합니다.

보존: nbp-vue-watch-review 폴더와 작성한 소스 파일, package-lock.json 및 node_modules를 그대로 남깁니다.

확인: 서버 터미널에 명령을 입력할 프롬프트가 돌아오고 대상 URL의 새 요청은 연결 실패합니다.

탭만 닫는 것은 서버 종료가 아닙니다. 새 요청이 계속 성공하면 다른 프로세스를 종료하지 말고 대상 포트와 자신이 연 터미널을 다시 확인합니다.
