Vue HTTP 요청 — 대기·성공·실패 화면 연결하기

Front-framework: Vue.js

수업일 · 2026-08-04 · 예상 40분

도시 목록을 가져오는 버튼을 눌렀습니다. 아직 응답이 없을 때, 목록이 도착했을 때, 파일을 찾지 못했을 때 화면은 어떻게 달라져야 할까요? 이번 목표는 HTTP 요청의 결과를 Vue 상태로 옮기고, 성공과 실패 모두에서 다시 누를 수 있게 만드는 것입니다.

HTTP는 브라우저와 서버가 요청·응답을 주고받는 약속입니다. GET은 여기서 파일을 읽어 달라는 요청입니다. Axios는 그 요청을 보내는 라이브러리이고, Vue는 받은 결과를 화면에 반영합니다. JSON은 객체·배열을 글자로 저장한 데이터 형식입니다. 외부 날씨 서비스 대신 같은 개발 서버의 가상 도시 파일을 사용합니다. 실제 날씨나 데이터베이스 저장 기능은 아닙니다.

이전 글의 파일은 필요하지 않습니다. ref, 클릭 이벤트, v-if·v-for를 다시 사용하며 async/await와 오류 처리는 아래에서 설명합니다. 시간 표시는 편성용 추정이며 학습자 실측이 아닙니다. Router·Pinia는 후속 편, POST·PUT·DELETE·원격 API·인증·interceptor·동시 요청은 이번 범위 밖입니다.

01새 폴더에서 요청 전 화면 열기

Mac 터미널·편집기·브라우저와 이미 설치된 Node.js·npm을 사용합니다. 기준 환경은 Node 26.7.0/npm 11.19.0입니다. 다른 환경은 미확인입니다. 명령을 찾지 못하면 여기서 멈추고 환경 준비 도움을 받으세요. 전역 설치나 기존 프로젝트 변경은 하지 않습니다.

현재 위치와 기존 파일을 확인합니다.

pwd

현재 폴더의 절대 경로가 나옵니다.

ls

기존 목록이 보이며 이 파일들은 수정하지 않습니다.

node --version

Node 버전이 표시됩니다.

npm --version

npm 버전이 표시됩니다. 이번 서버의 5183번 포트가 사용 중인지 봅니다.

lsof -nP -iTCP:5183 -sTCP:LISTEN

출력이 없고 오류 문구도 없으면 이 조회에서 대기 서버를 찾지 못한 것입니다. 이때 종료 코드 1은 가능합니다. 목록이 나오면 다른 프로세스를 종료하지 말고 멈추세요. --strictPort가 시작 때도 충돌을 확인합니다.

편집기나 파일 탐색기에서 현재 위치 아래에 새 빈 폴더 nbp-vue-request-review를 만듭니다. 같은 이름이 이미 있으면 덮어쓰지 말고 멈추세요. 이후 모든 파일은 이곳에만 둡니다.

cd nbp-vue-request-review

정상 이동은 출력이 없습니다.

pwd

nbp-vue-request-review로 끝나는 새 학습 폴더의 경로여야 합니다. 편집기에서 이 폴더를 여세요.

ls -A

새 폴더이므로 출력이 없어야 합니다.

mkdir src public

출력 없이 두 하위 폴더가 만들어집니다. 편집기에서 아래 여섯 파일을 새로 만들고 전체 내용을 저장합니다. 별도 프로젝트 생성 명령은 실행하지 않습니다.

vite.config.js 전체 — Vue 파일 처리 기능을 연결합니다. appType: 'mpa'는 없는 데이터 주소를 첫 HTML로 대신 응답하지 않게 해 진짜 404를 관찰하기 위한 설정입니다. 이 편은 Router를 사용하지 않습니다.

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  appType: 'mpa'
})

public/cities.json 전체 — public 파일은 주소에서 public을 빼고 요청합니다.

[
  { "id": "seoul", "name": "서울", "temperature": 24 },
  { "id": "suwon", "name": "수원", "temperature": 22 }
]

src/App.vue 전체:

<script setup>
import { ref } from 'vue'
import axios from 'axios'

const url = ref('/cities.json')
const status = ref('idle')
const loading = ref(false)
const cities = ref([])
const errorMessage = ref('')
const slowDemo = ref(false)

async function loadCities() {
  loading.value = true
  status.value = 'loading'
  cities.value = []
  errorMessage.value = ''
  try {
    // 관찰용: 실제 요청을 보내기 전에 800ms 기다립니다.
    if (slowDemo.value) {
      await new Promise(resolve => setTimeout(resolve, 800))
    }
    const response = await axios.get(url.value)
    cities.value = response.data
    status.value = 'success'
  } catch (error) {
    errorMessage.value = error.response
      ? 'HTTP ' + error.response.status
      : '서버에 연결할 수 없습니다'
    status.value = 'error'
  } finally {
    loading.value = false
  }
}
</script>

<template>
  <main>
    <h1>도시 요청 복습</h1>
    <label>
      요청 주소
      <select v-model="url" :disabled="loading">
        <option value="/cities.json">정상 파일</option>
        <option value="/missing-cities.json">없는 파일</option>
      </select>
    </label>
    <label>
      <input v-model="slowDemo" type="checkbox" :disabled="loading">
      대기 관찰용 800ms 지연
    </label>
    <button :disabled="loading" @click="loadCities">
      {{ loading ? '요청 처리 중' : '가져오기 / 재시도' }}
    </button>
    <p>상태: {{ status }}</p>
    <p v-if="status === 'idle'">아직 요청하지 않았습니다.</p>
    <p v-else-if="status === 'loading'">결과를 기다립니다.</p>
    <section v-else-if="status === 'success'">
      <p>도시 {{ cities.length }}개</p>
      <ul>
        <li v-for="city in cities" :key="city.id">
          {{ city.name }}: {{ city.temperature }}°C
        </li>
      </ul>
    </section>
    <p v-else role="alert">가져오기 실패: {{ errorMessage }}</p>
  </main>
</template>

ref는 변화를 화면에 알리는 값입니다. 코드에서는 .value로 바꾸고 template에서는 이름만 씁니다. status는 표시할 결과 종류, loading은 버튼을 잠글지 결정합니다. 처음에는 idle이고 아직 요청하지 않았습니다.

설치와 실행을 차례로 합니다.

npm install

성공하면 로컬 node_modules와 package-lock.json이 만들어집니다. 네트워크·버전 오류가 나면 임의 버전으로 바꾸지 말고 멈춥니다.

npm run dev

http://127.0.0.1:5183/가 표시되며 서버가 터미널을 계속 사용합니다. 포트 오류면 다른 서버를 끄지 말고 중단하세요. 이 터미널을 서버 전용으로 남깁니다.

브라우저 실행

대상: http://127.0.0.1:5183/

조작: 여섯 파일을 저장하고 npm run dev를 시작한 뒤 대상 주소를 열어 첫 화면을 봅니다. 아직 가져오기 버튼은 누르지 않습니다.

확인: 도시 요청 복습 제목, 상태: idle, 아직 요청하지 않았습니다. 문구와 활성화된 가져오기 / 재시도 버튼이 보입니다.

완료 예시

실제 첫 화면은 상태: idle, 아직 요청하지 않았습니다.였으며 도시 목록은 없었습니다. 가져오기 / 재시도 버튼은 활성화되어 있었습니다.

02대기에서 성공으로 바꾸기

먼저 예상하세요. 버튼을 누르는 순간과 응답이 도착한 뒤에는 어느 문구가 보여야 할까요?

async 함수 안의 await axios.get(...)는 응답이 올 때까지 그 함수의 다음 줄을 기다립니다. 브라우저 전체를 멈추지는 않습니다. 성공하면 Axios 응답의 data를 cities에 넣고 success로 바꿉니다. finally는 성공·실패 어느 쪽에서도 대기를 끝냅니다.

로컬 파일은 빨라서 loading을 눈으로 놓칠 수 있습니다. 대기 관찰용 800ms 지연을 체크하면 요청을 보내기 전에 일부러 0.8초 기다립니다. setTimeout이 시간이 지난 뒤 resolve를 호출하면 await가 이어집니다. 이것은 UI 상태를 볼 학습 장치이지 실제 서버가 느리거나 요청이 이미 진행 중이라는 증거가 아닙니다. 체크하지 않은 실행도 별도로 해 보세요.

브라우저 실행

대상: http://127.0.0.1:5183/

조작: 정상 파일을 선택하고 대기 관찰용 800ms 지연을 체크한 뒤 가져오기 / 재시도를 누릅니다. 성공 후 public/cities.json의 서울 temperature만 24에서 27로 바꿔 저장하고 다시 가져오기를 누릅니다. 마지막으로 24로 복원해 저장하고 다시 요청합니다.

확인: 클릭 직후 상태: loading과 잠긴 버튼, 이어서 상태: success와 도시 2개, 서울: 24°C·수원: 22°C가 보입니다. 파일 값을 바꾼 뒤 다시 요청하면 해당 도시의 표시도 달라집니다.

왜 저장만 하는 것과 다시 요청하는 것이 다를까요? cities는 이전 응답을 담고 있습니다. 서버의 파일을 바꿨다고 이미 받은 응답 객체가 저절로 바뀌지는 않습니다. 새 GET 응답을 다시 대입해야 합니다. 변형 후 서울 값을 원래대로 돌려 다음 단계에 사용하세요.

완료 예시

실제 상태는 idle → loading → success로 바뀌었고 대기 중 버튼은 잠겼습니다. 원형은 서울 24°C·수원 22°C였습니다. JSON을 27로 저장해도 재요청 전에는 서울 24°C가 남았고, 다시 요청하자 서울 27°C로 바뀌었습니다. 새 JSON 응답을 대입했기 때문입니다. 24로 복원하고 요청하자 원형으로 돌아왔습니다.

03없는 파일의 실패를 복구하기

정상 데이터가 한 번 보였어도 다음 요청이 성공한다는 보장은 없습니다. 없는 파일을 선택하면 도시가 0개인 성공일까요, 오류일까요? 빈 배열을 반환한 성공과 HTTP 404는 다릅니다.

Axios의 기본 설정에서는 404 응답이 catch로 넘어옵니다. error.response.status는 HTTP 상태 번호입니다. 서버 연결 자체가 실패하면 응답이 없을 수 있어 먼저 error.response가 있는지 확인합니다. 요청 시작 때 지난 목록과 오류 문구를 비우므로 오래된 성공 목록을 새 결과처럼 보여 주지 않습니다.

브라우저 실행

대상: http://127.0.0.1:5183/

조작: 개발자 도구의 Network 탭을 열고 없는 파일을 선택해 가져오기 / 재시도를 누릅니다. missing-cities.json 요청의 Status를 봅니다. 정상 파일로 선택을 되돌리고 같은 버튼을 다시 누릅니다.

확인: 없는 파일은 Network에서 404이고 화면은 상태: error, 가져오기 실패: HTTP 404입니다. loading이 끝나 버튼과 선택 상자가 다시 활성화됩니다. 정상 파일 재시도는 상태: success와 도시 2개로 돌아옵니다.

Network는 Chrome에서 메뉴의 보기 → 개발자 정보 → 개발자 도구로 열 수 있습니다. 요청을 누른 뒤 missing-cities.json 행을 선택해 상태 번호를 보세요. HTML이 200으로 반환된다면 성공으로 기록하지 말고 vite.config.js의 mpa 설정과 서버 재시작을 확인합니다. 설정을 고쳤다면 자신이 실행한 서버 터미널에서 Ctrl+C 후 npm run dev로 다시 시작합니다.

작은 변형으로 선택 주소만 정상→없음→정상으로 바꿨습니다. 오류 뒤에도 같은 함수를 다시 부를 수 있는 이유를 말해 보세요. finally가 없다면 오류 상태는 기록됐는데 버튼은 계속 잠기는 문제가 생길 수 있습니다.

완료 예시

실제 네트워크 응답은 GET /missing-cities.json → HTTP 404였고, 화면에 상태: error와 가져오기 실패: HTTP 404가 보였습니다. 버튼은 다시 활성화되었습니다. /cities.json을 재요청하자 도시 2개와 success가 돌아왔습니다. 404가 성공으로 바뀐 것이 아니라 새 요청이 성공한 것입니다.

04이번 서버만 종료하기

다른 작업의 터미널이나 서버는 건드리지 않습니다. 브라우저 탭만 닫으면 개발 서버는 남습니다.

브라우저 실습 종료

대상: http://127.0.0.1:5183/

종료 방식: 서버 터미널 Ctrl+C

조작: 이번 폴더에서 npm run dev를 실행한 터미널만 선택해 Ctrl+C를 누릅니다. 같은 대상 주소를 새로고침해 새 요청을 시도합니다.

보존: nbp-vue-request-review 학습 폴더와 여섯 원본 파일, package-lock.json, node_modules를 삭제하지 않고 남깁니다.

확인: 터미널에 입력 프롬프트가 돌아오고 새 요청은 연결 실패가 됩니다. 이전 화면이 남아 있는 것만으로 서버 실행 여부를 판단하지 않습니다.

완료 예시

이번 서버 터미널에서 Ctrl+C로 종료한 뒤 새 요청은 연결 실패가 되었습니다. 학습 파일은 그대로 남았습니다. 없는 파일 요청의 HTTP 404는 실행 중인 서버의 응답이고, 종료 뒤 연결 실패는 서버에 연결할 수 없는 상태입니다.
