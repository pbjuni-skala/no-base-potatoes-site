연구소 관제판의 표시 이름을 입력하면 아래 안내도 달라집니다. 이번에는 문단을 직접 찾아 글자를 넣지 않고, 입력과 문단이 같은 상태를 바라보도록 연결합니다. 입력으로 바꿀 때와 버튼의 코드로 바꿀 때를 비교해 봅니다.

한 개의 Vue 화면 파일에서 ref, 보간, v-model, 클릭 함수를 복습합니다. 이전 글의 파일은 필요하지 않습니다. 가상의 표시 이름만 쓰며 학습용 자격 증명도 필요 없습니다. 실제 자격 증명인 비밀번호·API 키나 실제 이름은 입력하지 않습니다. 예상 30분은 편성용 추정이며 실측하지 않았습니다.

01새 프로젝트에서 준비 화면 열기

macOS 터미널, 편집기, Chrome·Edge 같은 브라우저를 사용합니다. Node.js는 개발 도구를 실행하고, npm은 프로젝트가 쓸 패키지를 설치합니다. Node 22.18 이상인 22 계열, 24.12 이상인 24 계열 또는 26 계열을 권장합니다. Node와 npm이 이미 준비돼 있어야 합니다. 없으면 설치를 추측해서 진행하지 말고 여기서 도움을 받으세요.

파일 탐색기에서 기존 프로젝트 밖에 새 빈 폴더 nbp-vue-input-review를 만듭니다. 이름이 이미 있으면 덮어쓰지 말고 다른 새 폴더를 고르세요. 편집기로 이 폴더를 열고 그 폴더의 터미널을 엽니다. 이후 파일 경로는 모두 이 폴더 기준입니다.

현재 위치와 버전을 각각 확인합니다.

pwd
node --version
npm --version

정상이라면 자신이 만든 새 폴더 경로와 버전 번호가 나옵니다. 다른 프로젝트 경로, 명령을 찾을 수 없다는 오류, 지원 범위 밖 Node라면 멈춥니다.

이번 서버가 쓸 5176번 포트가 비어 있는지 확인합니다.

lsof -nP -iTCP:5176 -sTCP:LISTEN

프로세스 행이 없으면 다음으로 갑니다. 행이 나오면 이미 사용 중이므로 멈추세요. 다른 프로세스를 강제로 종료하거나 다른 포트로 몰래 바꾸지 않습니다.

편집기에서 아래 다섯 파일을 새로 만듭니다. src는 직접 만드는 하위 폴더입니다. 파일 이름에 .txt가 붙지 않도록 확인하고 모두 UTF-8로 저장하세요.

package.json 전체입니다. 사용할 패키지 버전과 npm run dev의 실제 실행 내용을 정합니다. 127.0.0.1은 내 컴퓨터에서만 접속하는 주소이고 --strictPort는 포트가 차 있으면 다른 포트로 옮기지 않고 멈추게 합니다.

{
  "name": "nbp-vue-input-review",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5176 --strictPort"
  },
  "dependencies": {
    "vue": "3.5.42"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "6.0.9",
    "vite": "8.3.0"
  }
}

vite.config.js 전체입니다. Vite는 개발 서버 도구이고, Vue 플러그인은 .vue 파일을 브라우저가 실행할 수 있게 처리합니다. import는 다른 파일이나 패키지에서 필요한 기능을 가져오는 문법입니다.

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
})

index.html 전체입니다. #app 자리에 Vue 화면이 붙고 src/main.js가 실행됩니다.

<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>관제판 표시 이름</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>

src/main.js 전체입니다. App.vue 화면으로 앱을 만들고 앞의 id="app"에 연결합니다. 이후 실습에서는 이 연결 파일을 수정하지 않습니다.

import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')

src/App.vue 전체입니다. SFC는 화면 하나의 JavaScript와 HTML 틀 등을 .vue 파일에 모으는 형식입니다. 지금은 화면 틀인 <template>만 사용합니다. <h1>은 큰 제목, <p>는 문단을 표시합니다.

<template>
  <main>
    <h1>관제판 표시 이름</h1>
    <p>입력 연결 준비</p>
  </main>
</template>

새 프로젝트 터미널에서 필요한 패키지를 설치합니다. 네트워크가 필요하며 이 폴더에 node_modules와 package-lock.json이 생깁니다. 전역 설치가 아닙니다.

npm install

오류 없이 명령이 끝나야 합니다. 네트워크·권한·버전 오류라면 다음 명령으로 넘어가지 말고 원인을 확인하세요. sudo나 전역 설정 변경으로 우회하지 않습니다. 이어서 개발 서버를 시작합니다.

npm run dev

정상이라면 터미널에 http://127.0.0.1:5176/가 표시됩니다. 이 터미널은 서버가 실행 중이므로 열어 둡니다. 포트 충돌이면 중단하고, 이미 실행 중인 다른 서버 화면을 자신의 성공 결과로 세지 않습니다. index.html 파일을 더블클릭하는 대신 다음 주소로 접속하세요.

02상태의 값을 문장에 표시하기

상태는 화면이 지금 기억하는 값입니다. ref('감자 연구원')는 Vue가 변경을 감지할 수 있는 상태를 만듭니다. 따옴표 안의 문자는 문자열이고 displayName은 그 상태를 가리키는 이름입니다. const로 선언한 이름 자체를 교체하지 않아도 ref 안의 값은 바꿀 수 있습니다.

src/App.vue 전체를 아래로 바꾸고 저장합니다. <script setup>에는 상태와 함수를, <template>에는 화면 틀을 씁니다. {{ displayName }}은 그 값을 글자로 보여 주는 보간입니다. 이처럼 최상위에 선언한 ref는 template에서 .value 없이 읽습니다.

열기 전에 예상해 보세요. 안내에는 displayName이라는 철자가 나올까요, 따옴표 안의 값이 나올까요?

<script setup>
import { ref } from 'vue'

const displayName = ref('감자 연구원')
</script>

<template>
  <main>
    <h1>관제판 표시 이름</h1>
    <p>현재 표시 이름: {{ displayName }}</p>
  </main>
</template>

작은 변형: ref(...) 안의 문자열만 새싹 연구원으로 바꾸세요. 저장하고 새로고침한 뒤 바뀐 결과를 확인합니다. 문단을 직접 고치지 않았는데 표시가 달라진 이유를 말해 보세요. 다음 단계 전에 초기 문자열은 감자 연구원으로 복원하고 저장합니다.

이 한 줄은 앞 App.vue의 선언 줄을 교체하는 조각입니다. 보간 자리는 그대로이고 그 자리가 읽는 초기값이 달라졌습니다. 새로고침으로 시작값을 다시 만든 실험이며, 다음 단계에서는 열린 화면의 상태를 입력으로 바꿉니다.

03입력칸과 상태 연결하기

HTML의 입력칸은 그 자체로 편집할 수 있지만, 그것만으로 JavaScript 상태까지 바뀌지는 않습니다. v-model="displayName"은 텍스트 입력값과 이 상태를 연결합니다. 상태가 입력칸에 표시되고, 사용자가 확정한 입력은 상태에 들어갑니다. 문단의 보간은 그 상태를 읽습니다.

src/App.vue 전체를 아래 코드로 바꿉니다. label의 for와 input의 id가 같아 입력칸 이름이 연결됩니다. type="text"는 문자열 입력칸입니다. 먼저 달 연구원을 입력하면 입력칸과 문단 중 어디가 달라질지 예상하세요.

<script setup>
import { ref } from 'vue'

const displayName = ref('감자 연구원')
</script>

<template>
  <main>
    <h1>관제판 표시 이름</h1>
    <label for="display-name">표시 이름</label>
    <input id="display-name" type="text" v-model="displayName">
    <p>현재 표시 이름: {{ displayName }}</p>
  </main>
</template>

작은 변형: 이번에는 입력칸의 글자를 전부 지운 뒤 입력을 확정하세요. 안내 앞부분까지 사라질까요? 직접 확인한 뒤 고정 글자와 보간으로 채워지는 부분의 차이를 설명해 보세요. 다음 단계는 새로고침해 감자 연구원으로 시작합니다.

04버튼의 코드로 같은 상태 바꾸기

입력하지 않고 코드로 상태를 바꾸어 봅니다. 함수는 이름을 붙여 둔 동작 묶음입니다. resetName 함수 안의 displayName.value = '감자 연구원'은 ref가 담은 값을 바꿉니다. JavaScript의 함수 안에서는 .value로 접근합니다.

@click="resetName"은 버튼을 누를 때 함수를 실행하도록 연결합니다. 지금 함수를 실행한 결과를 넣는 것이 아니라 클릭 때 쓸 함수 이름을 연결한 것입니다. 먼저 입력을 바꾼 뒤 버튼을 누르면 입력칸과 문단은 각각 어떻게 될지 예상하세요.

src/App.vue 전체를 아래로 바꾸고 저장합니다.

<script setup>
import { ref } from 'vue'

const displayName = ref('감자 연구원')

function resetName() {
  displayName.value = '감자 연구원'
}
</script>

<template>
  <main>
    <h1>관제판 표시 이름</h1>
    <label for="display-name">표시 이름</label>
    <input id="display-name" type="text" v-model="displayName">
    <p>현재 표시 이름: {{ displayName }}</p>
    <button type="button" @click="resetName">이름 되돌리기</button>
  </main>
</template>

조작: src/App.vue를 저장하고 새로고침합니다. 입력칸을 달 연구원으로 바꾸어 확정한 뒤 이름 되돌리기 버튼을 누릅니다.

확인: 입력칸과 안내의 이름이 모두 감자 연구원으로 돌아갑니다.

버튼 클릭 후 정상이라면 입력칸에 감자 연구원, 문단에 현재 표시 이름: 감자 연구원이 보입니다. 바뀌지 않으면 @click의 함수 이름과 .value를 확인합니다. 상태 변경 뒤 화면 갱신은 Vue가 처리하므로 문단이나 입력칸을 직접 찾아 수정하는 코드는 없습니다.

작은 변형: 버튼이 이름을 대기 중으로 바꾸게 해 보세요. 초기값 선언은 그대로 두고 함수 안의 문자열 한 곳만 바꿉니다. 저장·새로고침 후 달 연구원을 입력하고 버튼을 누르세요. 처음 화면과 버튼을 누른 뒤 화면의 차이, 입력칸까지 함께 달라지는 이유를 설명해 보세요. 종료할 때 변형 코드는 그대로 남겨도 됩니다.

완료 예시

원형은 달 연구원 입력 후 클릭하면 입력칸·문단 모두 감자 연구원으로 돌아왔습니다. 변형은 앞 전체 App.vue에서 함수만 다음처럼 바꿉니다.

function resetName() {
  displayName.value = '대기 중'
}
옆으로 밀어서 비교 →
시점입력칸안내 문단
새로고침 직후감자 연구원현재 표시 이름: 감자 연구원
달 연구원 입력 확정달 연구원현재 표시 이름: 달 연구원
변형 버튼 클릭대기 중현재 표시 이름: 대기 중

초기값과 클릭 때 넣는 값은 다른 줄입니다. 버튼 → 함수 → ref의 값 변경 → v-model 입력칸과 보간 문단 갱신으로 이어집니다. 함수에서 바꾸는 것은 HTML 글자가 아니라 두 표시가 공유하는 상태입니다.

브라우저 실습 종료

대상: http://127.0.0.1:5176/

종료 방식: 서버 터미널 Ctrl+C

조작: 이번 서버 터미널에서 Ctrl+C를 누르고 프롬프트가 돌아오는지 봅니다. 같은 URL을 주소창에 다시 입력해 새 요청을 보냅니다.

확인: 새 요청은 연결 실패가 되고 저장한 파일들은 같은 폴더에 남습니다.

정상 결과는 서버 터미널이 입력 가능한 상태로 돌아오고 같은 URL의 새 요청이 실패하는 것입니다. 화면이 계속 새로 열리면 다른 서버가 응답하는지 확인하고 완료로 세지 않습니다. 연결 실패 문구는 브라우저마다 다릅니다. 기존 화면이 남아 있다는 사실만으로 서버가 살아 있다고 판단하지 않습니다.
