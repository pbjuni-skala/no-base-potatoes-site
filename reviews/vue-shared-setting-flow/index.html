Vue Pinia — 여러 컴포넌트에서 같은 설정 바꾸기

Front-framework: Vue.js

수업일 · 2026-08-04 · 예상 40분

설정 버튼은 위쪽 컴포넌트에 있고 온도 표시는 아래쪽 컴포넌트에 있습니다. 위에서 단위를 바꾸었을 때 아래 표시도 바뀌려면 두 컴포넌트가 같은 설정을 읽어야 합니다. 각자 초기값이 같은 변수를 만드는 것과 한 상태를 공유하는 것은 다릅니다.

Pinia는 Vue 앱의 여러 컴포넌트가 사용할 상태를 관리하는 라이브러리입니다. 저장소인 store에 상태와 변경 함수를 모아 둡니다. 여기서 공유는 같은 앱 안의 공유이며 다른 브라우저·사용자까지 동기화한다는 뜻이 아닙니다. ref, computed, 클릭과 컴포넌트를 사용하되 필요한 파일은 처음부터 제공합니다. 이전 글의 산출물은 필요 없습니다.

학습용 자격 증명도 필요 없고 실제 자격 증명·개인정보를 넣지 않습니다. 온도 20도는 가상 고정 데이터입니다. 40분은 실측하지 않은 편성용 추정입니다.

01새 프로젝트에서 준비 화면 열기

macOS 터미널, 편집기와 Chrome·Edge 같은 브라우저를 사용합니다. Node.js와 npm은 이미 설치되어 있어야 합니다. Node 22.18 이상인 22 계열, 24.12 이상인 24 계열 또는 26 계열을 사용하세요. Node는 개발 도구를 실행하고 npm은 필요한 패키지를 설치합니다. 설치되지 않았다면 여기서 도움을 받으세요.

파일 탐색기에서 기존 프로젝트 밖에 새 빈 폴더 nbp-vue-store-review를 만들고 편집기로 엽니다. 이름이 이미 있으면 덮어쓰지 말고 다른 새 폴더를 선택합니다. 아래 경로는 모두 그 폴더 기준이며, 이전 복습 파일은 필요 없습니다. 폴더의 터미널에서 각각 실행합니다.

pwd
node --version
npm --version

정상이라면 새 폴더의 절대 경로와 버전 번호가 나옵니다. 다른 프로젝트 경로나 지원하지 않는 버전이면 중단합니다. 이번에 사용할 포트도 확인합니다.

lsof -nP -iTCP:5185 -sTCP:LISTEN

프로세스 행이 없어야 합니다. 행이 나오면 다른 서버를 끄지 말고 멈추세요. 아래 다섯 파일을 편집기로 새로 만듭니다. src 폴더도 만들고 모두 UTF-8로 저장합니다.

package.json 전체입니다. 고정 버전으로 설치하며 --strictPort는 포트 충돌 때 다른 주소로 옮기지 않고 멈추게 합니다. 127.0.0.1은 자신의 컴퓨터에서 접속하는 주소입니다.

{
  "name": "nbp-vue-store-review",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5185 --strictPort"
  },
  "dependencies": {
    "vue": "3.5.42",
    "pinia": "3.0.4"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "6.0.9",

}

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({ plugins: [vue()] })

02두 컴포넌트가 같은 설정 사용하기

상태인 unit은 현재 단위를 담습니다. unitSymbol은 현재 상태를 기호로 계산한 getter이고, toggleUnit은 단위를 바꾸는 action입니다. 이 글의 setup store에서 ref는 state, computed는 getter, 함수는 action 역할을 합니다. return에 담아야 바깥에서 사용할 수 있습니다.

먼저 예상해 보세요. 버튼 컴포넌트만 눌렀는데 형제인 요약 컴포넌트의 온도도 달라질까요? 아래 순서대로 저장합니다. 아직 변경 중인 화면은 성공 결과로 보지 말고 모든 파일을 저장한 다음 새로고침합니다.

src/main.js 전체를 바꿉니다. createPinia()로 앱에서 쓸 Pinia를 만들고 use로 등록한 다음 화면을 붙입니다.

import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

createApp(App).use(createPinia()).mount('#app')

새 폴더 src/stores와 파일 src/stores/settings.js를 만듭니다. 아래가 전체입니다. defineStore의 첫 문자열 settings는 앱 안에서 저장소를 구별하는 고유 이름입니다. 조건 ? A : B는 조건이 맞으면 A, 아니면 B를 고르는 식입니다.

import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

export const useSettingsStore = defineStore('settings', () => {
  const unit = ref('celsius')
  const unitSymbol = computed(() => unit.value === 'celsius' ? '℃' : '℉')
  function toggleUnit() {
    unit.value = unit.value === 'celsius' ? 'fahrenheit' : 'celsius'
  }
  return { unit, unitSymbol, toggleUnit }
})

새 폴더 src/components와 파일 src/components/UnitToggler.vue를 만듭니다. 아래가 전체입니다. useSettingsStore()는 이 앱의 해당 저장소를 가져옵니다. 이 함수가 호출될 때마다 독립된 단위가 생기는 것은 아닙니다.

<script setup>
import { useSettingsStore } from '../stores/settings.js'

const settings = useSettingsStore()
</script>

<template>
  <section>
    <h2>단위 설정</h2>
    <p>설정 쪽 기호: {{ settings.unitSymbol }}</p>
    <button type="button" @click="settings.toggleUnit">단위 바꾸기</button>
  </section>
</template>

src/components/WeatherSummary.vue도 새로 만듭니다. 아래가 전체입니다. 원본 20은 섭씨 온도이며 화씨일 때만 20 × 9 ÷ 5 + 32로 바꾸어 표시합니다. Math.round는 계산 결과를 정수로 반올림합니다. 기호만 바꾸고 숫자는 그대로 두면 같은 온도를 표현할 수 없습니다.

<script setup>
import { computed } from 'vue'
import { useSettingsStore } from '../stores/settings.js'

const settings = useSettingsStore()
const displayTemp = computed(() =>
  settings.unit === 'celsius' ? 20 : Math.round(20 * 9 / 5 + 32)
)
</script>

<template>
  <section>
    <h2>관측 요약</h2>
    <p>표시 온도: {{ displayTemp }} {{ settings.unitSymbol }}</p>
    <p>공유 상태: {{ settings.unit }}</p>
  </section>
</template>

src/App.vue 전체를 바꿉니다. App이 두 화면 조각을 나란히 포함하므로 두 컴포넌트는 형제 관계입니다. 별도 파일의 컴포넌트를 import하고 그 이름을 태그처럼 써서 배치합니다.

<script setup>
import UnitToggler from './components/UnitToggler.vue'
import WeatherSummary from './components/WeatherSummary.vue'
</script>

<template>
  <main>
    <h1>공유 단위 설정</h1>
    <UnitToggler />
    <WeatherSummary />
  </main>
</template>

이 예제는 settings.unit처럼 저장소를 통해 읽습니다. const { unit } = settings로 문자열만 꺼내 놓으면 이후 상태와의 반응형 연결을 잃을 수 있어 사용하지 않습니다. 저장소 속성은 컴포넌트에서 .value를 붙이지 않지만, 저장소 함수 내부의 unit ref는 unit.value로 바꿉니다.

브라우저 실행

대상: http://127.0.0.1:5185/

조작: main.js를 교체하고 settings.js, UnitToggler.vue, WeatherSummary.vue를 만들고 App.vue를 교체해 모두 저장합니다. 새로고침 후 단위 바꾸기를 한 번 누릅니다.

확인: 처음에는 설정 쪽 기호 ℃, 표시 온도 20 ℃, 공유 상태 celsius가 보입니다. 클릭 후 두 기호가 ℉로 바뀌고 표시 온도 68 ℉, 공유 상태 fahrenheit가 보입니다.

화면이 깨지면 파일 경로와 Pinia 등록 순서를 확인하고 멈춥니다. 두 기호 중 하나만 변한다면 두 파일이 같은 useSettingsStore를 쓰는지 확인합니다.

작은 변형: 버튼을 한 번 더 눌러 보세요. 바뀐 숫자가 새로운 원본이 된 것인지, 고정 섭씨 원본에서 다시 계산한 것인지 설명합니다. 버튼 두 번 뒤 원형의 섭씨 상태로 되돌아옵니다.

03공유 설정과 새로고침 뒤 초기값 구별하기

화면 안의 두 컴포넌트가 값을 함께 읽는 것과, 브라우저를 새로 열어도 값을 기억하는 것은 다른 요구입니다. 이 예제는 메모리에만 상태를 두고 외부 저장 코드를 작성하지 않았습니다.

예상해 보세요. 버튼으로 화씨를 선택한 뒤 브라우저를 새로고침하면 화씨가 유지될까요? 서버는 계속 켜 두고 먼저 실험합니다.

브라우저 실행

대상: http://127.0.0.1:5185/

조작: 원형 코드에서 단위 바꾸기를 눌러 화씨로 만든 뒤 브라우저 새로고침을 누릅니다. 새로고침 전후 두 컴포넌트의 단위와 온도를 비교합니다.

확인: 새로고침 전 68 ℉였다가 새로고침 뒤 두 기호는 ℃, 표시 온도는 20 ℃, 공유 상태는 celsius로 보입니다.

새로고침하면 앱이 다시 시작하면서 store의 초기값으로 상태를 만듭니다. Pinia를 설치했다는 사실만으로 디스크나 서버에 값이 영구 저장되지는 않습니다. 코드 편집 시 개발 도구가 일부 상태를 유지하는 동작과 혼동하지 않도록 이 실험에서는 반드시 브라우저 새로고침을 합니다.

작은 변형: src/stores/settings.js의 초기값 한 줄을 아래로 바꾸고 저장한 뒤 새로고침합니다. 다른 파일은 바꾸지 않습니다. 두 컴포넌트가 어디에서 초기값을 가져오는지 설명하세요.

const unit = ref('fahrenheit')

결과를 확인했으면 그 줄을 const unit = ref('celsius')로 복원하고 새로고침합니다. 원형 20 ℃로 돌아온 뒤 종료 단계로 갑니다.

공유 여부는 같은 store를 읽는 것으로, 재시작 뒤 값은 초기값과 별도 저장·복원 로직으로 결정됩니다. 이번에는 저장·복원 로직이 없으므로 파일에 적힌 초기값이 기준입니다.

04서버를 종료하고 학습 파일 남기기

지금까지 만든 파일을 저장합니다. 새로고침은 실행 중 메모리 상태를 초기화하지만 파일을 지우지는 않습니다. 이 단계에서는 삭제 명령을 실행하지 않습니다. 정상이라면 터미널 프롬프트와 브라우저의 연결 실패 안내가 보입니다.

종료 방식: 서버 터미널 Ctrl+C

확인: 서버 터미널에 명령을 입력할 프롬프트가 돌아오고 대상 URL의 새 요청은 연결 실패합니다.

탭만 닫는 것은 서버 종료가 아닙니다. 새 요청이 계속 성공하면 다른 프로세스를 종료하지 말고 대상 포트와 자신이 연 터미널을 다시 확인합니다.

// stores/settings.js
export const useSettingsStore = defineStore('settings', () => {
  const unit = ref('celsius')
  const unitSymbol = computed(() => unit.value === 'celsius' ? '℃' : '℉')
  function toggleUnit() {
    unit.value = unit.value === 'celsius' ? 'fahrenheit' : 'celsius'
  }
  return { unit, unitSymbol, toggleUnit }
