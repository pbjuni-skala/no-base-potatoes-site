도시가 세 개 있을 때 검색 결과에 한 개만 남으면 나머지는 지워진 걸까요? 원본 배열과 화면에 보여 줄 배열을 따로 두고, 검색어를 지워 세 도시가 돌아오는지 확인합니다.

이번에는 v-for와 고유한 key, computed 필터, v-if/v-else의 빈 결과를 복습합니다. 이전 글의 파일 없이 시작합니다. ref는 Vue가 변경을 추적하는 값이고 v-model은 입력과 상태를 연결한다는 정도를 떠올리면 됩니다. 필요한 사용법은 아래에 다시 설명합니다. 학습용 자격 증명도 필요 없으며 실제 자격 증명·개인정보는 넣지 않습니다. 35분은 편성용 추정으로 실측하지 않았습니다.

01새 프로젝트에서 준비 화면 열기

macOS 터미널, 편집기와 Chrome·Edge 같은 브라우저를 사용합니다. Node.js와 npm은 이미 설치되어 있어야 합니다. Node 22.18 이상인 22 계열, 24.12 이상인 24 계열 또는 26 계열을 사용하세요. Node는 개발 도구를 실행하고 npm은 필요한 패키지를 설치합니다. 설치되지 않았다면 여기서 도움을 받으세요.

파일 탐색기에서 기존 프로젝트 밖에 새 빈 폴더 nbp-vue-list-review를 만들고 편집기로 엽니다. 이름이 이미 있으면 덮어쓰지 말고 다른 새 폴더를 선택합니다. 아래 경로는 모두 그 폴더 기준이며, 이전 복습 파일은 필요 없습니다. 폴더의 터미널에서 각각 실행합니다.

pwd
node --version
npm --version

정상이라면 새 폴더의 절대 경로와 버전 번호가 나옵니다. 다른 프로젝트 경로나 지원하지 않는 버전이면 중단합니다. 이번에 사용할 포트도 확인합니다.

lsof -nP -iTCP:5181 -sTCP:LISTEN

프로세스 행이 없어야 합니다. 행이 나오면 다른 서버를 끄지 말고 멈추세요. 아래 다섯 파일을 편집기로 새로 만듭니다. src 폴더도 만들고 모두 UTF-8로 저장합니다.

package.json 전체입니다. 고정 버전으로 설치하며 --strictPort는 포트 충돌 때 다른 주소로 옮기지 않고 멈추게 합니다. 127.0.0.1은 자신의 컴퓨터에서 접속하는 주소입니다.

{
  "name": "nbp-vue-list-review",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5181 --strictPort"
  },
  "dependencies": {
    "vue": "3.5.42"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "6.0.9",
    "vite": "8.3.0"
  }
}

vite.config.js 전체입니다. Vite는 개발 서버이며 Vue 플러그인이 .vue 파일을 처리합니다.

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({ plugins: [vue()] })

index.html 전체입니다. #app에 Vue 화면을 연결합니다.

<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">

  </head>
  <body>
    <div id="app"></div>

src/main.js 전체입니다. import는 다른 파일이나 패키지에서 기능을 가져옵니다.

import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')

src/App.vue 전체입니다. Vue의 SFC는 JavaScript와 화면 틀을 한 .vue 파일에 모으는 형식입니다. 지금은 화면 틀인 template만 사용합니다.

<template>
  <main>
    <h1>도시 목록</h1>
    <p>실습 준비</p>
  </main>
</template>

새 폴더의 터미널에서 패키지를 설치합니다. 네트워크가 필요하며 이 폴더에 node_modules와 package-lock.json이 생깁니다. 전역 설치가 아닙니다.

npm install

정상이라면 오류 없이 끝납니다. 권한·네트워크·버전 오류가 있으면 멈추고 원인을 확인합니다. sudo나 전역 설정 변경으로 우회하지 않습니다. 이어서 서버를 시작합니다.

npm run dev

터미널에 http://127.0.0.1:5181/가 표시되어야 합니다. 서버 터미널은 열어 둡니다. 파일을 더블클릭하지 말고 다음 주소를 여세요.

02배열의 항목을 목록으로 펼치기

배열은 순서가 있는 값의 묶음입니다. 각 항목은 id와 name을 가진 객체입니다. v-for="city in cities"는 항목을 하나씩 city라는 이름으로 읽어 같은 태그를 반복합니다. :key="city.id"는 Vue가 항목의 정체를 구별하는 표식이며 화면에 출력하는 글자가 아닙니다. 검색으로 위치가 달라져도 id는 유지되므로 순번을 key로 삼지 않습니다.

예상해 보세요. li는 코드에 한 번 쓰였는데 화면에는 몇 줄이 생길까요? src/App.vue 전체를 아래로 바꿔 저장합니다. JavaScript에서는 ref 내용에 .value로 접근하고, template의 최상위 ref는 .value 없이 씁니다.

<script setup>
import { ref } from 'vue'

const cities = ref([
  { id: 'seoul', name: '서울' },
  { id: 'suwon', name: '수원' },
  { id: 'busan', name: '부산' },
])
</script>

<template>
  <main>
    <h1>도시 목록</h1>
    <p>원본: {{ cities.length }}개</p>
    <ul>
      <li v-for="city in cities" :key="city.id">{{ city.name }}</li>
    </ul>
  </main>
</template>

브라우저 실행

대상: http://127.0.0.1:5181/

조작: src/App.vue 전체를 위 코드로 저장하고 대상 URL을 새로고침합니다. 세 도시의 순서를 읽습니다.

확인: 원본: 3개 아래에 서울, 수원, 부산이 순서대로 표시됩니다.

작은 변형: { id: 'suwon', name: '수원' }의 이름만 수원시로 바꿔 저장합니다. 무엇은 달라지고 무엇은 그대로일까요? 시도 후 이름을 수원으로 복원합니다.

03원본을 지우지 않고 검색 결과 계산하기

검색어는 직접 바꾸는 상태이고 검색 결과는 그 상태에서 계산한 값입니다. computed에 전달한 함수가 읽은 반응형 값이 바뀌면 새 결과를 계산할 수 있습니다. 여기서는 원본 cities와 입력 search에 의존합니다.

filter는 조건을 만족하는 항목으로 새 배열을 만들며 원본 배열에서 항목을 삭제하지 않습니다. city => ...는 각 항목을 받아 조건을 검사하는 짧은 함수 표현입니다. includes는 이름에 검색 문자열이 들어 있는지 확인합니다. 모든 문자열에는 빈 문자열이 포함되므로 검색칸을 비우면 전체가 선택됩니다.

먼저 예상하세요. 검색어가 수일 때 원본 개수도 1이 될까요? src/App.vue 전체를 다음으로 바꿔 저장합니다.

<script setup>
import { ref, computed } from 'vue'

const cities = ref([
  { id: 'seoul', name: '서울' },
  { id: 'suwon', name: '수원' },
  { id: 'busan', name: '부산' },
])
const search = ref('')
const filteredCities = computed(() =>
  cities.value.filter(city => city.name.includes(search.value))
)
</script>

<template>
  <main>
    <h1>도시 목록</h1>
    <label>도시 검색 <input v-model="search" type="text"></label>
    <p>원본: {{ cities.length }}개 / 검색 결과: {{ filteredCities.length }}개</p>
    <ul v-if="filteredCities.length > 0">
      <li v-for="city in filteredCities" :key="city.id">{{ city.name }}</li>
    </ul>
    <p v-else>일치하는 도시가 없습니다.</p>
  </main>
</template>

브라우저 실행

대상: http://127.0.0.1:5181/

조작: src/App.vue 전체를 위 코드로 저장하고 새로고침합니다. 검색칸에 수를 입력하고 한글 조합을 확정한 뒤 결과와 원본 개수를 비교합니다.

확인: 처음에는 원본: 3개 / 검색 결과: 3개이며, 수 입력 확정 후 원본: 3개 / 검색 결과: 1개와 수원이 보입니다.

한글 조합 중에는 v-model 갱신이 보류될 수 있으므로 입력을 확정한 뒤 비교합니다. v-if는 결과가 있을 때 목록을 그리고, 바로 이어진 v-else는 결과가 없을 때 안내 문장을 그립니다. 목록이 비어도 원본 데이터가 손상된 것은 아닙니다.

작은 변형: 검색어만 제주로 바꿔 보세요. 빈 화면과 안내 문장이 있는 화면은 어떻게 다를까요? 이어 검색칸을 완전히 비우고 원본이 남아 있는지 확인합니다. 다음 단계는 코드 원형을 그대로 둡니다.

04서버를 종료하고 학습 파일 남기기

지금까지 만든 파일을 저장합니다. 새로고침은 실행 중 메모리 상태를 초기화하지만 파일을 지우지는 않습니다. 이 단계에서는 삭제 명령을 실행하지 않습니다. 정상이라면 터미널 프롬프트와 브라우저의 연결 실패 안내가 보입니다.

브라우저 실습 종료

대상: http://127.0.0.1:5181/

종료 방식: 서버 터미널 Ctrl+C

조작: 자신이 npm run dev로 시작한 해당 서버 터미널에서 Ctrl+C를 누르고 대상 URL을 브라우저에서 새로고침합니다.

보존: nbp-vue-list-review 폴더와 작성한 소스 파일, package-lock.json 및 node_modules를 그대로 남깁니다.

확인: 서버 터미널에 명령을 입력할 프롬프트가 돌아오고 대상 URL의 새 요청은 연결 실패합니다.

탭만 닫는 것은 서버 종료가 아닙니다. 새 요청이 계속 성공하면 다른 프로세스를 종료하지 말고 대상 포트와 자신이 연 터미널을 다시 확인합니다.
