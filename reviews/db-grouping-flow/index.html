학생 네 명을 조회했는데 결과가 한 줄 또는 세 줄이 됩니다. 학생이 사라진 걸까요? 이번에는 개별 학생 목록을 요약값으로 바꾸는 집계를 실행합니다. 학생을 먼저 고르는 조건과 인원수를 계산한 뒤 그룹을 고르는 조건을 구분하는 것이 목표입니다.

기초 SELECT·WHERE·ORDER BY 실행 경험을 전제로 하되 전체 SQL을 다시 제공합니다. JOIN을 먼저 알 필요는 없습니다. 실제 학생 정보가 아닌 합성 데이터를 사용합니다.

01이번 편의 별도 DB 준비

개인 Mac의 Docker Desktop·PostgreSQL 15 이미지·DBeaver가 준비되어 있어야 합니다. 설치 시간은 예상 시간에 포함하지 않습니다. PostgreSQL은 데이터를 저장하고 SQL을 처리하는 서버이고 DBeaver는 그 서버로 SQL을 보내는 도구입니다. 이전 편의 DB가 남아 있다고 가정하지 않습니다.

학습용 자격 증명은 아래 고정 dummy 값만 사용하고, 실제 자격 증명은 입력하지 않습니다. 기존 수업·팀 DB에는 실행하지 마세요.

터미널에서 기존 자원부터 확인합니다.

docker version
docker ps -a --format '{{.Names}} {{.Status}} {{.Ports}}'
docker image inspect postgres:15 --format '{{.Id}}'
lsof -nP -iTCP:55434 -sTCP:LISTEN

Client Context가 내 Mac의 desktop-linux이고 Server 정보가 나와야 합니다. 컨테이너 목록에 nbp-review-db-grouping이 없어야 하고 포트 조회에는 출력이 없어야 합니다. 이름·포트가 사용 중이거나 이미지·서버가 없다면 멈추세요. 기존 자원을 종료·삭제하거나 버전을 임의로 바꾸지 않습니다.

다음 명령은 이번 편 전용 서버를 만듭니다. --pull=never는 새 다운로드를 막습니다. tmpfs는 임시 저장소이므로 컨테이너를 멈추면 데이터가 사라집니다. 보관할 실제 데이터를 넣지 마세요.

docker run --pull=never --name nbp-review-db-grouping -e POSTGRES_USER=nbp_student -e POSTGRES_PASSWORD=nbp_dummy_only -e POSTGRES_DB=nbp_review -p 127.0.0.1:55434:5432 --mount type=tmpfs,destination=/var/lib/postgresql/data,tmpfs-size=268435456 -d postgres:15
docker exec nbp-review-db-grouping pg_isready -U nbp_student -d nbp_review

컨테이너 ID와 accepting connections가 정상 출력입니다. 아직 응답이 없다면 잠시 뒤 두 번째 명령만 다시 실행합니다. 계속 실패하면 다음 SQL로 넘어가지 않습니다.

DBeaver에서 기존 연결을 수정하지 말고 PostgreSQL 새 연결을 만듭니다.

아래 문장을 위에서부터 한 문장씩 실행합니다. CREATE TABLE은 표의 틀, INSERT INTO는 데이터를 만듭니다. integer는 정수, text는 글자입니다. NOT NULL은 값 없음(NULL)을 허용하지 않는 조건이며, 빈 문자열 ''을 금지하는 뜻은 아닙니다. 글자는 작은따옴표로 감쌉니다.

CREATE TABLE students (
  student_id integer PRIMARY KEY,
  name text NOT NULL,
  grade integer NOT NULL
);

INSERT INTO students (student_id, name, grade)
VALUES (1, '가람', 1), (2, '나래', 2), (3, '다온', 2), (4, '라온', 3);

이미 표가 있다는 오류가 나면 삭제하거나 INSERT를 반복하지 말고 준비를 중복 실행했는지 확인하세요. 생성 성공 뒤 다음 단계의 전체 조회로 입력을 대조합니다.

02COUNT로 학생 수 하나 얻기

먼저 계산에 넣을 원본을 확인합니다. PRIMARY KEY인 학생 번호는 한 학생을 구별하며 중복될 수 없습니다.

SELECT student_id, name, grade FROM students ORDER BY student_id;

정상 출력은 다음 4행입니다. 다르면 연결과 준비를 확인하고 집계로 넘어가지 않습니다.

“학생 이름을 보여줘”가 아니라 “학생이 몇 명인지 알려줘”로 요구를 바꿉니다. COUNT(*)는 입력 행 수를 계산합니다. 여기서 *는 모든 열을 출력하라는 SELECT *와 다르게, 행을 세는 COUNT의 표기입니다. AS student_count는 계산 결과 열에 붙일 이름입니다.

다음 결과에 몇 행이 나오고 어떤 숫자가 들어갈지 각각 예상합니다.

SELECT COUNT(*) AS student_count
FROM students;

정상 출력은 1행·1열이고 그 칸의 값이 4입니다. 학생 네 명의 정보를 그대로 펼친 것이 아니라 인원수 하나로 요약한 것입니다.

작은 변형: 집계에 넣을 학생을 2학년으로 한정합니다.

SELECT COUNT(*) AS student_count
FROM students
WHERE grade = 2;

정상 값은 2이고 결과는 여전히 1행입니다. “결과가 1행이므로 학생이 1명이다”가 왜 틀렸는지 설명해 보세요. 값이 다르면 원본 네 건과 WHERE를 확인하고 INSERT를 반복하지 않습니다.

완료 예시

FROM students
WHERE grade = 2;

WHERE가 없는 원래 쿼리의 값은 4입니다. 변형 후에는 2지만 두 쿼리 모두 숫자 하나를 담은 1행을 반환합니다. 결과 행 수와 학생 수를 구분하세요.

03GROUP BY로 학년마다 한 줄 만들기

이번에는 2학년만이 아니라 각 학년의 인원이 필요합니다. GROUP BY grade는 학년이 같은 학생을 한 그룹으로 묶어 계산하라는 뜻입니다. 학년이 묶는 기준인 그룹 키입니다.

앞의 WHERE를 이어 쓰지 말고 아래 전체 문장으로 바꾸세요. 몇 그룹이 생길지 먼저 예상합니다.

SELECT grade, COUNT(*) AS student_count
FROM students
GROUP BY grade
ORDER BY grade;

정상 출력은 3행입니다.

결과 한 행은 이제 학생 한 명이 아니라 학년 하나의 요약입니다. 2학년의 나래와 다온이 원본에서 합쳐져 삭제된 것이 아닙니다. 조회 결과에서 인원수 2로 표현한 것입니다.

작은 변형: 이번 계산에서 1학년을 제외하려면 학생 행을 먼저 고릅니다.

SELECT grade, COUNT(*) AS student_count
FROM students
WHERE grade >= 2
GROUP BY grade
ORDER BY grade;

정상 출력은 2학년 2명·3학년 1명의 두 행입니다. WHERE가 먼저 학년 2 이상인 학생을 골라 그 학생들끼리 그룹을 만듭니다. 이것은 결과를 이해하기 위한 논리적 순서이지 DB 내부 작업의 물리적 실행 순서를 고정한 설명은 아닙니다.

name도 SELECT에 넣으면 어떨까요? 이 쿼리는 학년당 한 줄인데 2학년의 이름을 나래와 다온 중 하나로 정할 수 없습니다. PostgreSQL은 이 형태에서 집계하지도, 그룹 기준에 넣지도 않은 name을 SELECT하면 오류로 알립니다. 오류를 없애려고 name까지 GROUP BY에 추가하면 묶는 단위가 학년+이름으로 달라지므로 이번 목표의 해결이 아닙니다.

1학년을 제외하는 변형 답안

FROM students
WHERE grade >= 2
GROUP BY grade
ORDER BY grade;

04HAVING으로 인원 조건에 맞는 그룹 고르기

“2학년 학생”이 아니라 “학생이 두 명 이상인 학년”을 찾고 싶습니다. 첫 요구는 학생의 grade로 판단하지만, 두 번째는 그룹의 인원을 계산해야 판단할 수 있습니다.

아래 전체 쿼리는 앞의 WHERE를 제거해 전체 네 명에서 다시 시작합니다. HAVING COUNT(*) >= 2는 만들어진 그룹 중 인원수가 두 명 이상인 그룹만 남깁니다.

SELECT grade, COUNT(*) AS student_count
FROM students
GROUP BY grade
HAVING COUNT(*) >= 2
ORDER BY grade;

정상 출력은 grade=2, student_count=2인 1행입니다. 지금 데이터에서는 마침 2학년만 두 명 이상일 뿐, HAVING이 “2학년을 고르라”는 뜻은 아닙니다. 1학년이 세 명인 데이터였다면 그 그룹도 조건을 통과합니다.

작은 변형: HAVING 한 줄을 지우면 어떤 그룹이 돌아올지 예상하고 실행하세요.

SELECT grade, COUNT(*) AS student_count
FROM students
GROUP BY grade
ORDER BY grade;

정상 출력은 다시 세 학년입니다. WHERE와 HAVING 중 어느 것이 “계산에 넣을 학생”, 어느 것이 “인원을 계산한 그룹”을 고르는지 말로 설명하세요. 세 학년이 돌아오지 않으면 WHERE가 남았는지와 선택해 실행한 전체 문장을 확인합니다.

05원본 확인과 이번 DB 정리

조회가 저장된 데이터를 바꾸지는 않았는지 확인합니다. 문장이 둘이면 하나씩 실행하세요.

SELECT student_id, name, grade FROM students ORDER BY student_id;

정상 출력은 처음의 학생 번호 1·2·3·4와 이름·학년 네 건입니다. 오늘의 조회는 원본을 수정하지 않았습니다. 모든 SQL이 안전하다는 뜻은 아닙니다.

SQL과 결과를 기록하고 DBeaver에서 이번 연결만 연결 해제합니다. 더 연습할 예정이면 정리는 나중에 하세요.

정리 대상 종류: container

정리 대상 ID: nbp-review-db-grouping

정확한 이름의 nbp-review-db-grouping 컨테이너만 정리합니다. 터미널에서 이름과 저장 설정을 먼저 봅니다.

docker inspect nbp-review-db-grouping --format '{{.Name}} {{json .HostConfig.Mounts}}'

이름이 /nbp-review-db-grouping이고 /var/lib/postgresql/data의 Type이 tmpfs인지 확인합니다. 자신이 만든 컨테이너가 아니거나 설정이 다르면 멈춥니다. 확인한 이번 자원만 순서대로 정리합니다.

docker stop nbp-review-db-grouping
docker rm nbp-review-db-grouping
docker ps -a --filter name=nbp-review-db-grouping --format '{{.Names}}'

stop·rm은 해당 이름을 출력하고 마지막 목록은 비어 있어야 합니다. 오류가 나도 강제 옵션을 더하거나 다른 자원을 지우지 마세요. stop에서 임시 데이터가 사라지고 rm이 멈춘 컨테이너를 제거합니다. 다시 하려면 준비 단계부터 시작합니다. 이미지·DBeaver 연결 설정·SQL 스크립트는 남습니다.

이 문제의 students는 (1, 가람, 1학년), (2, 나래, 2학년), (3, 다온, 2학년), (4, 라온, 3학년)입니다. 아래 결과는 (1,1), (2,2), (3,1) 세 행입니다. 이 세 행은 무엇을 뜻하나요?

SELECT grade, COUNT(*) AS student_count
FROM students
GROUP BY grade
ORDER BY grade;

선택해서 확인하기

이 문제만의 students는 (1, 가람, 1학년), (2, 나래, 1학년), (3, 다온, 2학년), (4, 라온, 3학년)입니다. '학생이 두 명 이상인 학년'을 찾으려 합니다. 아래 SQL은 2학년 1명만 보여줍니다. 목표에 맞는 수정은?

SELECT grade, COUNT(*) AS student_count
FROM students
WHERE grade = 2
GROUP BY grade
ORDER BY grade;
정답 하나를 고르세요
