도시를 골랐을 뿐인데 아래 안내 문장이 바뀝니다. 브라우저가 도시 이름을 보고 알아서 안내를 찾는 것은 아닙니다. 선택 변경 → 선택값 읽기 → 객체에서 안내 찾기 → 화면 글자 바꾸기를 JavaScript로 연결해 봅니다.

이 글은 HTML 파일 하나로 끝납니다. 앞 글의 파일, 외부 날씨 API, 서버, 설치가 필요하지 않습니다. 안내 문구는 연습용으로 만든 가상 행사 정보입니다. 학습용 자격 증명도 필요 없으며 실제 자격 증명은 입력하지 않습니다. 예상 25분은 편성용 추정으로 실측하지 않았습니다.

교안의 위도·경도 대신 가상 안내 문장을 쓰며, 여러 파일 대신 하나에 HTML과 JavaScript를 담습니다. 좌표나 도시 상식을 외우는 과제가 아닙니다. 날씨 요청·CSS 배치·모듈·Vue까지 완료한 것으로 세지 않습니다.

01새 파일로 빈 화면 열기

편집기와 Chrome·Edge 같은 브라우저를 사용합니다. 파일 탐색기에서 새 빈 학습 폴더를 만드세요. 이름이 이미 있으면 기존 폴더를 쓰지 말고 다른 새 이름을 정합니다. 기존 교안·프로젝트 파일은 건드리지 않습니다.

그 폴더에 index.html을 새로 만들고 아래 전체 내용을 UTF-8로 저장합니다. 이름이 index.html.txt가 되지 않게 확장자를 확인하세요. 파일 저장 방법이 낯설면 여기서 도움을 받습니다.

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>도시 안내 연습</title>
</head>
<body>
</body>
</html>

<!doctype html>은 HTML 문서임을 알려 줍니다. head에는 문자 설정과 탭 제목, body에는 화면에 보일 내용을 둡니다. 지금은 body가 비어 있으므로 내용 없는 화면이 정상입니다. meta charset은 한글을 UTF-8로 읽게 합니다.

브라우저 실행

대상: ./index.html

조작: 새 학습 폴더의 index.html을 저장하고 파일 탐색기에서 브라우저로 엽니다. 주소가 그 파일을 가리키는지 확인합니다.

확인: 탭 제목에 도시 안내 연습이 보입니다. 페이지 본문은 비어 있습니다.

정상 화면은 빈 본문입니다. 파일의 코드가 글자로 보이거나 다른 화면이면 파일 이름·확장자·연 브라우저 탭을 확인하고 멈춥니다. 서버나 Live Server는 시작하지 않습니다. 앞으로도 같은 ./index.html을 수정하고 저장한 뒤 새로고침합니다.

완료 예시

새 파일에 아래 전체 코드를 저장해 열었습니다.

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>도시 안내 연습</title>
</head>
<body>
</body>
</html>

탭 제목은 도시 안내 연습, 본문의 글자는 없었습니다. 기존 파일이 없는 새 학습 폴더에서 시작했고 서버는 실행하지 않았습니다.

02선택 상자와 안내를 한 파일에 연결하기

코드를 읽은 뒤, 아직 도시를 고르지 않은 첫 화면에 서울 안내가 나올지 생각해 보세요. 함수를 등록하는 것과 실행하는 것이 같은 순간인지 확인할 예정입니다.

학습용 index.html의 내용 전체를 아래 코드로 교체합니다. 기존 다른 파일에는 붙여 넣지 마세요. select는 선택 상자, 그 안의 option은 선택지입니다. label의 for="city"는 id="city"인 선택 상자의 설명이라는 뜻입니다. id는 이 문서에서 요소를 찾을 이름입니다.

선택지에서 사람에게 보이는 서울과 프로그램이 읽을 value="seoul"을 구분하세요. 안내 객체의 키도 seoul이어서 같은 이름으로 찾을 수 있습니다. 처음의 비활성 선택지는 도시를 아직 고르지 않았음을 보여 줍니다.

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>도시 안내 연습</title>
</head>
<body>
  <h1>도시 안내</h1>
  <label for="city">도시 선택</label>
  <select id="city">
    <option value="" selected disabled>도시를 고르세요</option>
    <option value="seoul">서울</option>
    <option value="busan">부산</option>
  </select>
  <p id="guide">선택한 도시의 안내가 여기에 나옵니다.</p>

  <script>
    const guides = {
      seoul: "서울: 감자 수프 시식은 1번 부스입니다.",
      busan: "부산: 감자 샌드위치 시식은 2번 부스입니다."
    };
    const city = document.getElementById("city");
    const guide = document.getElementById("guide");

    city.addEventListener("change", function () {
      const cityCode = city.value;
      guide.textContent = guides[cityCode];
    });
  </script>
</body>
</html>

script 안이 JavaScript입니다. 요소들 뒤에 놓았으므로 해당 요소를 만든 다음 찾습니다. document.getElementById("city")는 이 HTML 문서에서 그 ID의 요소를 가져옵니다. city에는 도시 이름 문자열이 아니라 선택 상자 자체를 연결합니다.

const는 이름을 만들어 값과 연결하는 선언입니다. guides 객체는 {} 안에서 키: 값으로 안내들을 묶습니다. seoul은 키, 따옴표 안의 안내 문장은 문자열 값입니다.

addEventListener("change", function () { ... })는 선택이 바뀌는 이벤트가 생길 때 실행할 함수를 등록합니다. 함수는 여러 동작을 묶은 코드입니다. 여기서는 등록할 때 함수 안을 바로 실행하는 것이 아니라 나중의 선택 변경을 기다립니다.

함수 안의 두 줄은 다음 역할입니다.

옆으로 밀어서 비교 →
코드이 화면에서 하는 일
const cityCode = city.value;그때 선택된 option의 value 문자열을 읽음
guides[cityCode]변수에 들어 있는 값과 같은 객체 키의 안내를 찾음
guide.textContent = ...;안내 문단의 기존 글자를 찾은 안내로 교체

DOM은 브라우저가 HTML의 요소를 프로그램으로 다룰 수 있게 만든 문서 구조입니다. textContent를 바꾸는 것은 화면 문단의 글자를 바꾸는 일이며, 디스크의 HTML 파일을 고쳐 저장하는 일은 아닙니다.

브라우저 실행

대상: ./index.html

조작: index.html 전체를 위 코드로 저장하고 같은 탭을 새로고침합니다. 아직 도시를 고르지 않습니다.

확인: 도시 안내 제목, 도시 선택 상자, 선택한 도시의 안내가 여기에 나옵니다. 문장이 보입니다.

처음부터 서울 안내가 나오지 않는 것이 정상입니다. 코드 등록과 실제 선택 변경을 구분하세요. 화면에 선택 상자가 없으면 body 부분을 포함한 전체 파일을 저장했는지 확인하고 다음 단계로 가지 않습니다.

완료 예시

아래 전체 HTML로 새로 열어 초기 상태를 확인했습니다.

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>도시 안내 연습</title>
</head>
<body>
  <h1>도시 안내</h1>
  <label for="city">도시 선택</label>
  <select id="city">
    <option value="" selected disabled>도시를 고르세요</option>
    <option value="seoul">서울</option>
    <option value="busan">부산</option>
  </select>
  <p id="guide">선택한 도시의 안내가 여기에 나옵니다.</p>

  <script>
    const guides = {
      seoul: "서울: 감자 수프 시식은 1번 부스입니다.",
      busan: "부산: 감자 샌드위치 시식은 2번 부스입니다."
    };
    const city = document.getElementById("city");
    const guide = document.getElementById("guide");

    city.addEventListener("change", function () {
      const cityCode = city.value;
      guide.textContent = guides[cityCode];
    });
  </script>
</body>
</html>

화면에는 도시 안내, 도시 선택, 도시를 고르세요, 선택한 도시의 안내가 여기에 나옵니다.가 보였습니다. 아직 안내 조회 함수가 선택 변경으로 실행되기 전입니다.

03도시를 바꿔 같은 함수 다시 실행하기

파일은 그대로 둡니다. 서울을 고른 뒤 부산, 다시 서울 순서로 바꿔 보세요. 마우스로 선택하거나 선택 상자에 키보드 초점을 옮겨 방향키와 Enter로 확정할 수 있습니다. 브라우저별 선택 조작 모양은 다를 수 있습니다.

브라우저 실행

대상: ./index.html

조작: 같은 index.html 탭에서 도시 선택을 서울 → 부산 → 서울 순서로 바꾸어 확정합니다.

확인: 안내가 서울의 1번 부스 → 부산의 2번 부스 → 서울의 1번 부스 순서로 바뀝니다.

정상 결과를 문구 전체로 비교하세요.

옆으로 밀어서 비교 →
선택읽는 value보이는 안내
서울seoul서울: 감자 수프 시식은 1번 부스입니다.
부산busan부산: 감자 샌드위치 시식은 2번 부스입니다.
다시 서울seoul서울: 감자 수프 시식은 1번 부스입니다.

안내 문장이 아래로 쌓이지 않고 같은 문단에서 교체됩니다. textContent =로 새 글자를 대입하기 때문입니다. 문장이 바뀌지 않으면 저장·새로고침 여부, 두 ID의 철자, change 등록과 중괄호가 전체 코드와 같은지 확인합니다. 새 코드가 아닌 다른 파일을 연 경우도 확인하세요.

선택 상자가 값을 보관하고, 함수는 이벤트 때 그 값을 읽습니다. 객체는 조회할 안내를 가지고 있고, 결과 문단은 보여 줄 자리를 맡습니다. 한 요소가 이 역할을 모두 하는 것은 아닙니다.

완료 예시

실행한 함수는 아래 부분입니다. 재현할 파일 전체는 바로 앞 확인 지점의 HTML이며 추가 파일은 없습니다.

city.addEventListener("change", function () {
  const cityCode = city.value;
  guide.textContent = guides[cityCode];
});

같은 화면에서 서울 → 부산 → 서울로 바꿨을 때 다음 문장이 한 자리에서 차례로 보였습니다.

서울: 감자 수프 시식은 1번 부스입니다.
부산: 감자 샌드위치 시식은 2번 부스입니다.
서울: 감자 수프 시식은 1번 부스입니다.

선택 상자의 value는 각각 seoul, busan, seoul이었습니다. 세 문장이 동시에 쌓인 화면은 아닙니다.

04도시 하나를 추가해 연결 확인하기

작은 변형입니다. 제주 선택지를 추가하려면 두 군데가 함께 필요합니다. 선택지의 value="jeju"와 객체의 jeju 키입니다. 화면에 보이는 이름을 추가하는 것만으로 안내 데이터가 저절로 생기지는 않습니다.

먼저 제주를 선택했을 때 표시할 문장을 예상해 보세요. 기존 index.html에서 선택지와 객체 항목을 직접 추가해 봅니다. 안내 문장은 제주: 구운 감자 시식은 3번 부스입니다.로 정합니다. 기존 부산 항목 뒤에는 다음 항목을 구분하는 쉼표가 필요합니다. 이벤트 함수는 바꾸지 않습니다.

수정한 파일을 저장한 뒤 아래 조작으로 비교하세요. 전체 정답 코드는 시도 후 완료 예시에서 확인할 수 있습니다.

브라우저 실행

대상: ./index.html

조작: 직접 수정한 index.html을 저장하고 새로고침한 뒤 제주를 고릅니다. 이어서 부산을 골라 기존 선택도 확인합니다.

확인: 제주는 구운 감자 3번 부스 안내, 부산은 기존 샌드위치 2번 부스 안내를 보여 줍니다.

정상 결과는 제주를 고를 때 제주: 구운 감자 시식은 3번 부스입니다.이고, 부산은 이전과 같습니다. 함수에 도시마다 별도 조건을 추가하지 않아도 선택값과 키가 같으면 같은 조회 코드로 찾습니다.

제주를 고른 뒤 글자가 비면 value와 객체 키가 정확히 jeju로 같은지 확인하세요. JavaScript는 대소문자를 구분합니다. 일치하는 키가 없으면 조회 결과는 undefined이고, 이 코드의 textContent에는 빈 글자가 들어갑니다. 모든 도시가 멈추면 빠진 쉼표·따옴표를 먼저 확인합니다. 아래 완료 예시의 전체 코드로 복원하고 저장·새로고침하면 다시 확인할 수 있습니다. 오류 처리 코드를 추가하는 단계는 아닙니다.

왜 이벤트 함수는 그대로인데 새 도시의 안내가 나왔는지, value와 객체 키의 관계로 설명해 보세요. 다음 단계는 파일을 보존하므로 원형으로 되돌릴 필요는 없습니다.

완료 예시

다음 전체 파일을 저장하고 제주 → 부산으로 선택했습니다.

<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>도시 안내 연습</title>
</head>
<body>

    <option value="" selected disabled>도시를 고르세요</option>
    <option value="seoul">서울</option>
    <option value="busan">부산</option>
    <option value="jeju">제주</option>
  </select>

  <script>
    const guides = {
      seoul: "서울: 감자 수프 시식은 1번 부스입니다.",
      busan: "부산: 감자 샌드위치 시식은 2번 부스입니다.",
      jeju: "제주: 구운 감자 시식은 3번 부스입니다."
    };
    const city = document.getElementById("city");
    const guide = document.getElementById("guide");

    city.addEventListener("change", function () {
      const cityCode = city.value;
      guide.textContent = guides[cityCode];
    });
  </script>

제주 선택값 jeju는 제주: 구운 감자 시식은 3번 부스입니다., 부산 선택값 busan은 부산: 감자 샌드위치 시식은 2번 부스입니다.로 연결됐습니다. 함수는 그대로이고 선택지·데이터만 늘었습니다.

05탭을 닫고 학습 파일 남기기

이 실습은 브라우저가 로컬 파일을 읽어 실행했습니다. 서버를 시작하지 않았으므로 서버 종료 명령은 필요하지 않습니다. 탭을 닫아도 저장한 파일은 남습니다. 마지막 수정이 저장됐는지 확인하고 이번 탭만 닫으세요. 다른 작업 탭과 브라우저 전체를 닫을 필요는 없습니다.

브라우저 실습 종료

대상: ./index.html

종료 방식: 탭 닫기

조작: 이번 학습 폴더의 index.html을 연 탭만 닫고 파일 탐색기로 돌아갑니다.

보존: 새 학습 폴더와 index.html의 HTML·JavaScript 코드를 남겨 둡니다.

확인: 대상 탭이 닫혔고 학습 폴더에 index.html이 남아 있습니다.

정상 상태는 탭이 닫히고 파일이 보존된 것입니다. 파일이 보이지 않으면 삭제 명령을 실행하지 말고 저장 위치부터 확인하세요. 다시 연습할 때는 같은 파일을 다시 열어 도시를 선택합니다. 이전 탭의 선택 상태를 저장하는 기능은 만들지 않았습니다.

완료 예시

제주까지 추가한 index.html 탭을 닫았습니다. 닫힌 탭은 더 이상 조작할 수 없었고, 파일은 같은 경로에 그대로 남았습니다. 파일 안에는 아래 선택지와 데이터가 보존됐습니다.

<option value="jeju">제주</option>

위 조각은 보존 확인용이며 단독 실행 파일이 아닙니다. 전체 파일은 앞 확인 지점의 코드입니다. 실제 파일 삭제나 다른 프로세스 종료는 하지 않았습니다.
