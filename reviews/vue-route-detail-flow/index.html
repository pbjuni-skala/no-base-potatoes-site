Vue Router — 주소에 맞는 상세 화면 열기

Front-framework: Vue.js

수업일 · 2026-08-04 · 예상 40분

확인 지점 4개 펼치기
  1. 01루트 주소에서 목록 열기
  2. 02같은 상세 화면에서 도시 바꾸기
  3. 03없는 도시와 없는 경로 구분하기
  4. 04이번 서버만 종료하기

서울 상세를 본 뒤 수원 링크를 누르면 주소와 화면이 함께 바뀌어야 합니다. 이번 목표는 주소 규칙과 현재 주소의 값을 구분하고, 그 값으로 상세 데이터를 고르는 것입니다. 단순히 링크를 만드는 데서 멈추지 않고 다른 도시 이동·뒤로 이동·없는 도시·없는 경로까지 비교합니다.

Router는 주소에 맞는 화면 부품을 선택하는 도구입니다. RouterLink는 앱 안에서 이동할 링크, RouterView는 선택된 부품이 표시될 자리입니다. route는 현재 주소 정보이고 router는 이동을 실행하는 객체입니다. 이번 도시 데이터는 코드에 들어 있는 가상 값이며 서버에서 가져오지 않습니다. HTTP 요청 편의 파일 없이도 시작할 수 있습니다.

Vue 파일, 클릭 이벤트, v-if, computed를 다시 사용합니다. computed는 의존한 값이 바뀌면 결과를 다시 계산합니다. params의 뜻과 연결 방법은 아래에서 설명합니다. 시간은 편성용 추정이며 학습자 실측이 아닙니다. query·guard·lazy loading·인증·Pinia·API 결합과 배포 서버 설정은 이번 편에 넣지 않습니다.

01루트 주소에서 목록 열기

Mac 터미널·편집기·브라우저와 이미 설치된 Node.js·npm을 사용합니다. 기준 환경은 Node 26.7.0/npm 11.19.0이며 다른 환경은 미확인입니다. 기존 프로젝트에 파일을 덮어쓰지 않고 새 폴더에서 시작합니다.

먼저 현재 위치와 파일을 확인합니다.

pwd

현재 폴더의 절대 경로가 보입니다.

ls

기존 파일 목록이며 이 파일들은 수정하지 않습니다.

node --version

Node 버전이 보입니다. 명령을 찾지 못하면 환경 준비 도움을 받습니다.

npm --version

npm 버전이 보입니다. 여기서 전역 설치나 버전 변경은 하지 않습니다.

5184번 포트를 확인합니다. 포트는 같은 컴퓨터의 서버를 구분하는 번호입니다.

lsof -nP -iTCP:5184 -sTCP:LISTEN

출력이 없고 오류 문구도 없으면 대기 서버를 찾지 못한 것입니다. 이 경우 종료 코드 1은 가능합니다. 목록이 나오면 다른 프로세스를 종료하지 말고 멈추세요. 시작 명령의 --strictPort도 충돌을 확인합니다.

편집기나 파일 탐색기에서 현재 위치 아래에 새 빈 폴더 nbp-vue-router-review를 만듭니다. 같은 이름이 이미 있으면 덮어쓰지 말고 멈추세요.

cd nbp-vue-router-review

정상 이동은 출력이 없습니다.

pwd

nbp-vue-router-review로 끝나는 새 학습 폴더의 경로입니다. 이 폴더를 편집기에서 여세요.

ls -A

비어 있어 출력이 없어야 합니다.

mkdir src

출력 없이 src 폴더가 생깁니다. 아래 열 파일을 이름 그대로 새로 만들어 전체 내용을 저장하세요. 이전 실습 복사나 프로젝트 생성 명령은 필요하지 않습니다.

package.json 전체 — 실행 도구와 버전입니다.

{
  "name": "nbp-vue-router-review",
  "private": true,
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite --host 127.0.0.1 --port 5184 --strictPort"
  },
  "dependencies": {
    "vue": "3.5.42",
    "vue-router": "4.6.4"
  },
  "devDependencies": {
    "vite": "8.3.0",
    "@vitejs/plugin-vue": "6.0.9"
  }
}

vite.config.js 전체 — Vue 파일을 처리합니다. 이 편은 Vite의 기본 SPA 모드를 사용합니다. SPA는 하나의 HTML 안에서 주소에 따라 화면 부품을 바꾸는 앱 구조입니다.

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()]
})

index.html 전체:

<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>도시 상세 복습</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>

src/main.js 전체 — use(router)로 Vue 앱에 라우터를 연결합니다.

import { createApp } from 'vue'
import App from './App.vue'
import router from './router.js'

createApp(App).use(router).mount('#app')

src/cities.js 전체 — 다른 파일에서도 쓸 수 있도록 export로 내보냅니다.

export const cities = [
  { id: 'seoul', name: '서울', temperature: 24 },
  { id: 'suwon', name: '수원', temperature: 22 }
]

src/router.js 전체 — 주소 규칙과 표시할 컴포넌트를 연결합니다. :id는 고정 글자가 아니라 해당 위치에서 읽을 값의 이름입니다. 마지막 규칙은 앞의 어느 경로에도 맞지 않는 주소를 잡습니다.

import { createRouter, createWebHistory } from 'vue-router'
import HomeView from './HomeView.vue'
import DetailView from './DetailView.vue'
import NotFoundView from './NotFoundView.vue'

export default createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: HomeView },
    { path: '/cities/:id', component: DetailView },
    { path: '/:pathMatch(.*)*', component: NotFoundView }
  ]
})

src/App.vue 전체 — 제목과 링크는 유지하고 RouterView 자리만 주소에 맞게 바뀝니다.

<script setup>
import { RouterLink, RouterView, useRoute } from 'vue-router'

const route = useRoute()
</script>

<template>
  <main>
    <h1>도시 상세 복습</h1>
    <nav aria-label="도시 이동">
      <RouterLink to="/">목록</RouterLink>
      <span> | </span>
      <RouterLink to="/cities/seoul">서울</RouterLink>
      <span> | </span>
      <RouterLink to="/cities/suwon">수원</RouterLink>
      <span> | </span>
      <RouterLink to="/cities/unknown">없는 도시</RouterLink>
      <span> | </span>
      <RouterLink to="/nowhere">없는 경로</RouterLink>
    </nav>
    <p>현재 경로: {{ route.path }}</p>
    <RouterView />
  </main>
</template>

src/HomeView.vue 전체:

<script setup>
import { RouterLink } from 'vue-router'
import { cities } from './cities.js'
</script>

<template>
  <section>
    <h2>도시 목록</h2>
    <ul>
      <li v-for="city in cities" :key="city.id">
        <RouterLink :to="'/cities/' + city.id">
          {{ city.name }} 상세
        </RouterLink>
      </li>
    </ul>
  </section>
</template>

src/DetailView.vue 전체 — 현재 ID가 바뀔 때마다 선택 결과도 바뀌게 합니다.

<script setup>
import { computed } from 'vue'
import { RouterLink, useRoute, useRouter } from 'vue-router'
import { cities } from './cities.js'

const route = useRoute()
const router = useRouter()
const city = computed(() =>
  cities.find(item => item.id === route.params.id)
)
</script>

<template>
  <section>
    <p>주소에서 읽은 ID: {{ route.params.id }}</p>
    <template v-if="city">
      <h2>{{ city.name }} 상세</h2>
      <p>기온: {{ city.temperature }}°C</p>
    </template>
    <p v-else>해당 도시가 없습니다.</p>
    <button @click="router.back()">이전 화면</button>
    <RouterLink to="/">목록으로</RouterLink>
  </section>
</template>

src/NotFoundView.vue 전체:

<script setup>
import { RouterLink } from 'vue-router'
</script>

<template>
  <section>
    <h2>등록되지 않은 경로입니다.</h2>
    <RouterLink to="/">목록으로</RouterLink>
  </section>
</template>

find는 조건에 맞는 첫 도시 객체를 찾고, 없으면 undefined를 돌려줍니다. city가 없을 때는 v-else로 안내를 보여 주므로 없는 객체의 기온을 읽지 않습니다.

설치 후 서버를 시작합니다.

npm install

성공하면 이 폴더에 node_modules와 package-lock.json이 만들어집니다. 설치 오류면 임의 버전으로 바꾸지 말고 멈춥니다.

npm run dev

http://127.0.0.1:5184/가 표시됩니다. 이 터미널은 서버가 계속 사용하므로 닫지 않습니다. 충돌이면 다른 서버를 종료하지 말고 중단합니다.

브라우저 실행

대상: http://127.0.0.1:5184/

조작: 열 파일을 저장하고 npm run dev로 서버를 시작합니다. 대상 루트 주소부터 열고 현재 경로와 목록을 봅니다. 아직 상세 링크는 누르지 않습니다.

확인: 현재 경로: /, 도시 목록, 서울 상세·수원 상세 링크가 보입니다.

완료 예시

실제 첫 화면은 현재 경로: /와 도시 목록이었고 서울 상세·수원 상세 링크가 보였습니다. App의 공통 제목 아래 RouterView 자리에 HomeView가 표시되었습니다.

02같은 상세 화면에서 도시 바꾸기

서울 링크를 누르면 /cities/:id라는 글자가 주소에 그대로 나타날까요? 먼저 예상한 뒤 눌러 보세요. 실제 주소의 seoul 또는 suwon이 route.params.id로 들어옵니다. 규칙은 하나이지만 값은 달라질 수 있습니다.

RouterLink의 to는 목적지이고 RouterView는 도착한 화면을 그리는 자리입니다. 이 링크 이동은 앱을 통째로 새로고침하지 않습니다. router.back()은 브라우저 방문 기록에서 한 단계 뒤로 이동합니다. 반드시 이 글처럼 루트에서 시작해 링크를 누른 뒤 사용하세요. 직접 상세 주소로 들어오면 이전 기록이 다른 사이트일 수도 있습니다.

브라우저 실행

대상: http://127.0.0.1:5184/

조작: 루트 목록에서 서울 상세를 누릅니다. 이어서 상단 수원 링크를 누르고 이전 화면 버튼을 누릅니다. 다시 상단 수원 링크를 누른 뒤 브라우저의 뒤로 버튼도 한 번 눌러 봅니다.

확인: 서울에서는 현재 경로: /cities/seoul, ID: seoul, 서울 상세와 24°C가 보입니다. 수원에서는 /cities/suwon, ID: suwon, 수원 상세와 22°C로 바뀝니다. 각 뒤로 이동은 직전 서울 상세로 돌아옵니다.

작은 변형은 같은 상세 규칙에서 ID만 seoul→suwon으로 바꾸는 것입니다. 템플릿 파일을 새로 만들지 않았는데 제목과 기온이 함께 바뀌는 이유를 말해 보세요.

두 주소는 같은 DetailView를 사용하므로 컴포넌트가 재사용될 수 있습니다. onMounted는 컴포넌트를 처음 붙일 때 실행하는 함수라서 그 안에서만 도시를 고르면 이후 ID 변경을 놓칠 수 있습니다. 여기서는 computed가 반응형 값인 route.params.id를 읽으므로 현재 ID를 기준으로 다시 선택합니다.

완료 예시

실제 원형은 /cities/seoul → seoul → 서울 24°C, 변형은 /cities/suwon → suwon → 수원 22°C였습니다. 이전 화면 버튼과 브라우저 뒤로 버튼 모두 서울 상세로 돌아왔습니다. 주소 규칙을 추가한 것이 아니라 하나의 규칙에 들어가는 값을 바꾼 것입니다.

03없는 도시와 없는 경로 구분하기

/cities/unknown과 /nowhere는 모두 원하는 내용을 찾지 못합니다. 그렇다면 똑같은 컴포넌트가 표시될까요? 어느 단계에서 찾기에 실패했는지 먼저 예상해 보세요.

/cities/unknown은 /cities/:id에 맞습니다. 라우터는 DetailView를 선택할 수 있지만 cities 배열에서 id가 unknown인 객체를 찾을 수 없습니다. 반면 /nowhere는 도시 상세 규칙 자체에 맞지 않으므로 마지막 catch-all 규칙의 NotFoundView가 표시됩니다. 이 화면 안내는 브라우저 안의 선택 결과이며 HTTP 응답 상태 404를 보장하지 않습니다.

브라우저 실행

대상: http://127.0.0.1:5184/

조작: 상단 없는 도시 링크를 누른 뒤 ID와 안내를 봅니다. 이어서 없는 경로 링크를 눌러 표시되는 제목을 비교합니다. 목록으로 링크를 눌러 루트로 복구합니다.

확인: 없는 도시에서는 /cities/unknown과 ID: unknown, 해당 도시가 없습니다.가 보입니다. 없는 경로에서는 /nowhere와 등록되지 않은 경로입니다.가 보이며 도시 ID 문단은 없습니다. 목록으로를 누르면 도시 목록이 돌아옵니다.

변형한 것은 링크의 목적지뿐입니다. “라우터가 어느 컴포넌트를 골랐는가”와 “그 컴포넌트가 어느 도시를 찾았는가”를 나눠 설명해 보세요. 어느 안내에서나 목록으로 돌아갈 수 있어 빈 화면에 갇히지 않습니다.

완료 예시

실제로 /cities/unknown에서는 ID unknown과 해당 도시가 없습니다.가 보였습니다. /nowhere에서는 등록되지 않은 경로입니다.가 보였고 도시 ID는 없었습니다. 앞은 DetailView의 데이터 찾기 실패, 뒤는 catch-all로 선택한 NotFoundView입니다. 목록으로 링크를 누르자 /의 도시 목록이 돌아왔습니다.

04이번 서버만 종료하기

이동 기록 확인을 마치면 이번 서버만 멈춥니다. 탭을 닫는 것과 서버 종료는 다릅니다.

브라우저 실습 종료

대상: http://127.0.0.1:5184/

종료 방식: 서버 터미널 Ctrl+C

조작: 이번 폴더에서 npm run dev를 실행한 서버 터미널만 골라 Ctrl+C를 누릅니다. 브라우저에서 루트 대상 주소를 다시 열어 새 요청을 보냅니다.

보존: nbp-vue-router-review 학습 폴더, 열 원본 파일, package-lock.json과 node_modules는 삭제하지 않고 남깁니다.

확인: 서버 터미널에 입력 프롬프트가 돌아오고 루트 주소의 새 요청은 연결 실패가 됩니다. 남아 있는 화면에서 내부 링크가 동작하는 것은 서버가 살아 있다는 증거가 아닙니다.

이미 로드된 JavaScript로는 서버 없이도 일부 화면 이동이 가능할 수 있습니다. 그래서 종료 확인은 내부 링크가 아니라 루트 주소의 새 요청으로 합니다.

완료 예시
