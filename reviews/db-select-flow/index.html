학생 목록에서 이름만 조회하면 학년은 사라진 걸까요? 2학년만 조회하면 다른 학생은 지워질까요? 같은 데이터를 두고 SQL의 한 부분씩 바꾸며 확인해 봅시다. 목표는 문장 암기가 아니라 원하는 결과를 얻으려면 어느 부분을 바꿔야 하는지 설명하는 것입니다.

이 글은 DB 4일 과정 중 기초 조회 한 편입니다. 학사 관리 실습의 맥락을 가져오되 실제 학생 정보나 과제 정답이 아닌 합성 데이터 네 건을 사용합니다. 전체 과제 제출을 대신하지 않습니다.

01학생 네 명을 담을 별도 공간 준비

개인 Mac에 Docker Desktop과 DBeaver가 준비되어 있다는 전제입니다. PostgreSQL은 데이터를 저장하고 SQL을 처리하는 DBMS, DBeaver는 SQL을 보내고 결과를 보여주는 클라이언트입니다. DBeaver만 열었다고 DB 서버가 생기지는 않습니다.

기존 수업 DB를 건드리지 않도록 PostgreSQL 15 컨테이너를 하나 만듭니다. 컨테이너는 따로 실행하는 DB 서버입니다. 127.0.0.1:55432는 내 Mac에서 접속할 주소와 포트입니다. 설치·드라이버 준비가 안 됐다면 여기서 멈추고 준비 도움을 받으세요. 예상 시간에는 설치 시간을 포함하지 않습니다.

터미널에서 현재 환경을 확인합니다. Docker 연결 오류가 나면 Docker Desktop 실행 상태부터 확인하고 다음 단계로 진행하지 않습니다.

docker version
docker ps -a --format '{{.Names}} {{.Status}} {{.Ports}}'
docker image inspect postgres:15 --format '{{.Id}}'
lsof -nP -iTCP:55432 -sTCP:LISTEN

Client의 Context가 내 Mac의 desktop-linux이고 Server 정보도 출력되는지 확인합니다. 컨테이너 목록에 nbp-review-db-select가 없어야 하고 마지막 포트 조회는 출력이 없어야 합니다. 같은 이름·포트를 누가 쓰고 있다면 삭제·종료하지 말고 멈춥니다. 이미지가 없다는 오류도 준비 미완료입니다. 다른 버전으로 임의 대체하지 않습니다.

다음은 이번 글 전용 컨테이너를 만드는 명령입니다. --pull=never는 실행 중 이미지를 새로 내려받지 않도록 합니다. tmpfs는 임시 메모리 저장소이므로 컨테이너를 멈추면 실습 데이터가 사라집니다. 실제 운영이나 파일 보관용 설정이 아닙니다. 오류가 나면 다른 자원을 정리하지 말고 이름·포트·이미지를 다시 확인합니다.

docker run --pull=never --name nbp-review-db-select -e POSTGRES_USER=nbp_student -e POSTGRES_PASSWORD=nbp_dummy_only -e POSTGRES_DB=nbp_review -p 127.0.0.1:55432:5432 --mount type=tmpfs,destination=/var/lib/postgresql/data,tmpfs-size=268435456 -d postgres:15
docker exec nbp-review-db-select pg_isready -U nbp_student -d nbp_review

긴 컨테이너 ID와 accepting connections가 보이면 접속할 수 있습니다. no response면 잠시 뒤 두 번째 명령만 다시 실행합니다. 계속 실패하면 멈춥니다.

DBeaver에서 기존 연결을 고치지 말고 PostgreSQL 새 연결을 만듭니다.

접속 대상부터 확인합니다.

SELECT current_database(), current_user;

결과가 nbp_review, nbp_student인지와 편집기에 연결된 포트가 55432인지 함께 확인합니다. 다른 복습 편도 DB·사용자 이름은 같으므로 포트가 다르면 멈추고 연결을 바로잡습니다. 자동 커밋(Auto-commit) 상태인지 확인한 뒤 아래 두 문장을 위에서부터 하나씩 실행합니다. 다른 연결의 설정은 바꾸지 않습니다.

CREATE TABLE students (
  student_id integer PRIMARY KEY,
  name text NOT NULL,
  grade integer NOT NULL
);

INSERT INTO students (student_id, name, grade)
VALUES (1, '가람', 1), (2, '나래', 2), (3, '다온', 2), (4, '라온', 3);

students는 표 이름입니다. 가로 한 줄인 행은 학생 한 명, 세로 열은 번호·이름·학년처럼 같은 종류의 정보를 담습니다. integer는 정수, text는 글자입니다. PRIMARY KEY는 번호가 중복되거나 비어 있지 않게 하고, NOT NULL은 값이 없지 않게 합니다. CREATE TABLE은 표의 틀을 만들고 INSERT INTO는 지정한 열 순서로 데이터를 넣습니다. 글자는 작은따옴표로 감싸고 세미콜론은 문장의 끝입니다. 제약조건 설계는 후속에 남깁니다.

첫 문장은 생성 성공, 두 번째는 영향받은 행이 4개인 것을 확인합니다. 이미 표가 있다는 오류가 나면 삭제하거나 INSERT를 반복하지 마세요. 준비를 중복 실행했는지 확인하고 다음 조회로 현재 상태를 먼저 봅니다.

02SELECT를 바꾸면 열이 달라진다

실행하기 전에 몇 행·몇 열이 나올지 예상해 보세요. FROM students는 읽을 표, SELECT 뒤 이름들은 결과에 보여줄 열입니다. ORDER BY student_id는 번호 순으로 보려는 약속입니다.

SELECT student_id, name, grade
FROM students
ORDER BY student_id;

정상 출력은 4행·3열입니다.

작은 변형: 첫 줄에서 , grade만 지우고 실행하세요. 행과 열 중 무엇이 줄어들까요? “학년이 화면에 없다”와 “저장된 학년을 삭제했다”가 같은 뜻인지 설명해 보세요. 표가 없다는 오류라면 준비 단계의 연결·CREATE TABLE 결과를 확인합니다. 다른 DB의 같은 이름 표에서 대신 실행하지 않습니다.

03WHERE를 바꾸면 포함되는 행이 달라진다

2학년만 보려면 다음 문장 전체로 바꾸세요. WHERE grade = 2는 각 학생의 학년을 검사해서 조건이 참인 행만 결과에 남깁니다. 여기서 =는 새 값을 넣는 대입이 아니라 같은지 비교하는 조건입니다. 어떤 학생이 남을지 먼저 고른 뒤 실행합니다.

SELECT student_id, name, grade
FROM students
WHERE grade = 2
ORDER BY student_id;

정상 결과는 2행·3열, 번호 2(나래)와 3(다온)입니다.

작은 변형: WHERE grade = 2 한 줄만 지우고 실행합니다. 다시 네 명이 보일까요? 결과에 없던 학생이 돌아오는 이유를 설명해 보세요. 예상과 다르면 실행한 선택 영역에 WHERE가 포함됐는지, 같은 연결인지 확인합니다. 화면을 맞추려고 INSERT를 다시 실행하지 않습니다.

보여줄 열과 조건에 쓸 열은 달라도 됩니다. 이름만 SELECT하더라도 students의 grade로 조건을 검사할 수 있습니다. “학년 열을 보여주기”와 “2학년 학생만 고르기”는 다른 요구입니다.

04ORDER BY를 바꾸면 결과 순서가 달라진다

학년이 높은 학생부터, 같은 학년이면 번호 작은 학생부터 보고 싶습니다. 아래 전체 문장에는 WHERE가 없으므로 다시 네 명을 대상으로 합니다.

SELECT student_id, name, grade
FROM students
ORDER BY grade DESC, student_id ASC;

DESC는 큰 값부터, ASC는 작은 값부터입니다. 두 번째 기준은 첫 기준이 같은 행끼리 비교합니다. 먼저 순서를 적고 실행 결과와 비교하세요. 정상 출력의 번호 순서는 4 → 2 → 3 → 1입니다. 같은 2학년에서는 번호가 작은 나래가 먼저입니다.

작은 변형: 첫 번째 DESC만 ASC로 바꿔 실행하세요. 학년 순서와 같은 학년 안의 순서가 각각 어떻게 되는지 설명합니다. 예상과 다르면 두 열 뒤의 방향을 따로 읽으세요. 뒤의 ASC 하나가 앞의 기준까지 바꾸지는 않습니다.

05원본을 확인하고 이번 공간만 정리

조회 문장을 여러 번 바꿨지만 원래 학생들은 그대로일까요? 다음 출력은 처음의 번호 1·2·3·4와 이름·학년 네 건이어야 합니다.

SELECT student_id, name, grade
FROM students
ORDER BY student_id;

이 글의 단순 조회는 저장된 행·값을 수정하지 않았습니다. 모든 SQL이 안전하다는 뜻은 아닙니다. 오늘은 준비의 CREATE/INSERT 이후 조회만 했습니다.

SQL과 결과를 먼저 기록하고 DBeaver에서 이번 연결만 연결 해제합니다. 정리 후에는 학생 표가 사라지므로 계속 연습하려면 여기서 멈춥니다.

정리 대상 종류: container

정리 대상 ID: nbp-review-db-select

정확한 이름의 nbp-review-db-select 컨테이너만 정리합니다. 다른 DB·파일·컨테이너는 건드리지 않습니다. 먼저 터미널에서 이름과 저장 방식을 확인합니다.

docker inspect nbp-review-db-select --format '{{.Name}} {{json .HostConfig.Mounts}}'

이름이 /nbp-review-db-select이고 /var/lib/postgresql/data를 대상으로 하는 Type: tmpfs 설정인지 확인합니다. 이름·설정이 다르거나 자신이 만든 자원인지 확신이 없으면 종료하지 말고 멈춥니다. 확인했다면 순서대로 실행합니다.

docker stop nbp-review-db-select
docker rm nbp-review-db-select
docker ps -a --filter name=nbp-review-db-select --format '{{.Names}}'

stop과 rm은 각각 해당 이름을 출력하고 마지막 목록은 비어 있어야 합니다. 오류가 나면 -f를 덧붙이거나 다른 자원을 지우지 말고 상태를 확인합니다. tmpfs 데이터는 stop에서 사라지고 rm은 멈춘 컨테이너를 제거합니다. 다시 하려면 컨테이너 생성·CREATE·INSERT부터 시작합니다. 이미지와 DBeaver 연결 설정·SQL 스크립트는 그대로 남습니다.

아래는 본문의 이름 기준 명령으로 보이는 정상 출력 예시입니다. $는 입력 줄을 구분하는 표시이므로 함께 입력하지 않습니다. 마지막 조회는 아무 이름도 출력하지 않고 다음 입력 줄로 돌아와야 합니다.

$ docker stop nbp-review-db-select
nbp-review-db-select
$ docker rm nbp-review-db-select
nbp-review-db-select
$ docker ps -a --filter name=nbp-review-db-select --format '{{.Names}}'
$

컨테이너 이름이 남거나 오류가 나면 정리 완료가 아닙니다. 실제 확인한 경우에만 완료로 기록하세요. 임시 데이터는 사라지지만 이미지·DBeaver 연결 설정·SQL 스크립트는 남습니다.

스스로 확인

선택해서 확인하기

이 문제의 students에는 (1, 가람, 1학년), (2, 나래, 2학년) 두 행만 있습니다. 아래 SQL에서 '2학년의 이름만' 보려면 무엇을 바꿔야 하나요?

SELECT name
FROM students
ORDER BY student_id;
정답 하나를 고르세요

선택해서 확인하기

이 문제의 students에는 (1, 가람, 1학년), (2, 나래, 2학년), (3, 다온, 2학년)이 있습니다. 아래 결과는 번호 3 → 2 → 1입니다. 학년 높은 순은 유지하면서 같은 학년에서는 번호 작은 순으로 보려면?

SELECT student_id, name, grade
FROM students
ORDER BY grade DESC, student_id DESC;
정답 하나를 고르세요

근거와 제외 범위

  • 백정열 「스마트 데이터 이해 및 활용」 2026-07-27 수업 PDF 461쪽, 특히 p26·38·70–89·91·93을 기반으로 재구성했습니다. 원문·페이지 이미지는 공개 복제하지 않습니다.
  • 교안은 PostgreSQL 14 또는 17과 DBeaver를 안내합니다. 이번에는 PostgreSQL 15 별도 환경으로 기초 SQL을 확인합니다. Docker는 기존 DB 보호를 위한 준비 수단이지 Day 1 학습 목표가 아닙니다.
  • SELECT 목록, 정렬, Docker tmpfs, DBeaver SQL 실행을 참고했습니다.
  • JOIN·집계·NULL·함수·수정/삭제·트랜잭션은 후속 범위입니다. 실제 데이터·팀 DB·외부 배포·과제 답안은 다루지 않습니다.
